# 唤醒天线轮换日志定位（2026-11-24）

## 当前策略：每16次S0换一根天线

每次唤醒从第一根使能天线开始，前15次S0保持；第16次切换到下一根，
第32次再切下一根，全使能时第128次回到天线0。每次SendWakeup重新归零。
到期则在S0优先停止，哪怕当次恰逢轮换边界也不再切天线。
HOLD表示保持，SWITCH只出现在16的整数倍；dwell_s0表示当前16次周期内的计数。
INFO/DEBUG采样前16次、每次轮换及每100次S0；错误不采样。

```text
[WAKEUP] HOLD s0=15 prev=0 requested=0 sw_current=0 ... dwell_s0=15/16
[WAKEUP] SWITCH s0=16 prev=0 requested=1 sw_current=1 ... dwell_s0=0/16
[WAKEUP] SWITCH s0=32 prev=1 requested=2 sw_current=2 ... dwell_s0=0/16
```

主机功能/诊断测试通过ASan/UBSan，验证保持期间不写天线增益、256次中断两轮轮换、
稀疏使能集合、重新启动计数重置和到期恰逢轮换边界。ARM及JTOOL编译链接通过。
本策略尚未重做板端验证；下方原板端日志均为“每次S0切换”的旧策略记录。

## 本次运行日志结论及修复

用户截图中 `PREP_SKIPPED prepared=0 mask=0x00` 后，首个S0约8.8ms时进入EMPTY_MASK，
申请天线255，再以 `state=5 result=2 stopped=1 elapsed_us=9280/9481` 结束。
这表示轮换准备没有执行，因参数错误停止，不是配置5000ms正常到期。
`active=0xFF` 说明八路sc_bcn均非零；saved/write为0说明软件保存值尚未初始化，
此时的mismatch=0xFF不等同于八次真实寄存器写入均失败。

现已恢复 `_wakeup_prepare_antennas()` 调用，切换写入成功后更新软件current，
并恢复先关闭所有BCN通道再单独开启选中通道的顺序。保留零掩码保护及诊断日志。
完整轮换主机测试和诊断测试均已通过ASan/UBSan，ARM/JTOOL构建通过。

## 运行

板子上重新上传本次构建的Test8710RFTxTone，用以下命令运行：

```bash
./Test8710RFTxTone 6 472300000 46 --wakeup-debug
```

然后输入u和 `3 5000 32`。不加--wakeup-debug时测试入口也会在Init之后启用INFO，
可看到启动、S0、切换汇总和停止。加该参数启用DEBUG，增加逐天线寄存器读回日志。
日志沿用Driver日志系统，控制台及原有8710log文件均可采集。
其他应用使用Driver时，Init之后调用：

```c
TK8710LogSetModuleMask(TK8710_LOG_MODULE_CORE);
TK8710LogSetLevel(TK8710_LOG_DEBUG);
```

完成定位后可改为WARN；INFO/DEBUG等级控制诊断采样和读回。打印和SPI读回会增加
中断处理时间，详细读回位于c008=0x80之后，避免插入原本1ms的切换等待窗口内。
仍应把启用详细诊断后的时序与关闭诊断后的RF行为分别验证。

## 关键记录

| 标记 | 内容及用途 |
|---|---|
| START | 模式、时长、ID、从0开始的组号、bcnbits、残留掩码/软件天线编号 |
| PREP | 如果调用初始化辅助函数，记录init_9及ant_en/rf_sel/bcn_en、最终交集 |
| STARTED | prepared标志、软件mask/current、0xc02c读回，检查初始化是否执行 |
| PREP_SKIPPED | 未执行轮换准备，掩码和保存的增益可能未初始化 |
| S0 | S0次数、中断状态、相邻S0间隔、已发送时间、目标时间、当前天线 |
| SWITCH | 旧天线、申请的新天线、函数返回后的软件编号、写入返回值、处理耗时 |
| REG | 各天线tx_config_28地址、保存值、写入值、读回值和sc_bcn/sc_da |
| ANT | 实际有BCN增益的通道掩码、预期写入不匹配掩码、读回失败掩码 |
| TRACKING_MISMATCH | 寄存器选择的天线与g_current_antenna不同，下一次仍可能从旧编号计算 |
| ACTIVE_MISMATCH | 读回的BCN非零通道不是申请的唯一天线 |
| EMPTY_MASK / INVALID_ANT | 无可用天线，保护性报错停止，避免死循环 |
| WRITE_FAIL / READ_FAIL | 地址、写入值或读取通道、S0次数及返回码 |
| STOP | 最终状态、停止原因、复位/屏蔽/清除返回值、累计S0和发送时间 |

S0及轮换详细记录只打印前16次（观察两轮8天线）和之后每100次。错误不采样。
ANT/REG读回只用于诊断，读取失败不会单独改变原发送结果；真正配置写失败仍按原流程停止。

## 当前工作区已发现的可疑状态

增加日志前读取到的代码中：

1. SendWakeup里的 `_wakeup_prepare_antennas()` 调用被注释；初次启动软件mask为0，
   原来的_next函数会无限循环。新增保护会输出EMPTY_MASK/INVALID_ANT并停止，
   不会默默恢复这行实验配置。
2. _select已改为单次按通道顺序写入，不再更新g_current_antenna。
   如果软件current一直为0，会出现反复申请天线1的日志。
3. 按0～7单次写入在从高编号切到低编号时，可能先开启新通道再关闭旧通道。
   轮换后的读回快照只能证明最终寄存器状态，不能证明切换瞬间没有两路同时使能。

本次以增加诊断为主，保留上述实验顺序、准备调用注释和软件current更新现状。
日志定位清楚后再决定恢复哪些配置。不要把有DEBUG输出等同于RF实际从某根天线发射。
