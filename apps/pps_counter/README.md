# RTK PPS 上升沿计数工具

监听核心板91脚 VO_LCDC_D9 / GPIO1_C2，即 `/dev/gpiochip1` line 18。
使用当前SDK的libgpiod 1.x接口申请输入和上升沿事件，成功后由内核GPIO中断通知应用。
不输出电平，不修改GPS周期，不访问UART，不停止tk8710_gw，不加入开机启动。

## 编译和运行

WSL中执行本目录 `bash build.sh`，产物为 `build_arm/pps_counter`。
SDK不在默认位置时，通过 `SDK_ROOT` 环境变量指定SDK根目录。

编译必须与SDK libgpiod保持一致：`-D_FILE_OFFSET_BITS=64 -D_TIME_BITS=64`。
旧测试程序漏加这些参数，会使32位ARM上的事件时间及类型结构布局不匹配，出现内核IRQ增长但应用计数为0；旧程序的零计数不能用于判定无脉冲。

将产物复制到板端后执行：

```sh
chmod +x ./pps_counter
./pps_counter 60   # 监听60秒，自动退出
./pps_counter 0    # 一直监听，Ctrl+C退出
```

不带参数默认60秒。每次上升沿打印累计次数、内核事件单调时间戳和相邻事件间隔；首次间隔显示0。
计数每次启动从0开始，退出时输出SUMMARY并释放GPIO。参数错误返回2，申请/读取失败返回1，正常结束返回0。
正常退出且计数为0只说明没有捕获到事件，不代表信号链路验证成功。

GPIO被其他消费者占用时程序会报错退出，不抢占。运行期间不要同时用gpioget/gpiomon申请此引脚。
本工具适合低频PPS诊断；没有添加消抖，毛刺也可能计数。libgpiod v1事件队列没有本工具可用的溢出序号，高频或长时间阻塞时不能保证无丢失。
时间戳是内核GPIO事件时间，不是8710硬件内部同步时间；应用输出存在调度延迟。

## 板端验证

`verify_board.py` 在192.168.100.239创建独立目录并上传运行60秒，采集运行前、中、后的引脚占用、中断项及业务/看门狗进程。
证据保存在本目录 `logs/<时间>/`。该脚本只运行计数程序，不制造脉冲或复位。
