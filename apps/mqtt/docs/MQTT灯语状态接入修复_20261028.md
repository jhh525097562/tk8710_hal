# MQTT 灯语状态接入修复

日期：2026-10-28。

## 原因与修复范围

原开发目录和 WSL SDK 的新版灯控读取 `/run/led/mqtt_status.json`，但 MQTT
主程序缺少状态模块调用，只有旧 `/run/led/mqtt.state` 输出。GitHub 基线
`0643b6b` 尚无新版 MQTT 状态模块；当前 GPS 扩展差异没有删除这些调用，
不能仅凭现有 Git 历史确定之前是哪一次同步覆盖了主程序。

本次在保留 GPS `count/avgsnr` 的当前主程序上恢复状态发布，并将现有
`mqtt_status.c/.h`、模块测试纳入 `rk3506b/apps/mqtt`。只统一本次 MQTT
修复文件，不批量覆盖 light/tdaemon；仓库的旧灯控仍能使用旧状态接口。

## 状态合同

| 触发点 | 状态 |
|---|---|
| 初始化 | connecting，ready=false，含当前进程身份 |
| CONNACK 成功 | 等待 SUBACK，仍不就绪 |
| 当前订阅 MID 的有效 SUBACK | connected，ready=true |
| 订阅拒绝、请求失败、broker 拒绝 | fault，ready=false |
| 断连 | reconnecting，立即撤销就绪；重连需新的 SUBACK |
| 连接/订阅等待超过 10 秒 | connection_timeout / suback_timeout |
| 主循环 | 按 CLOCK_MONOTONIC 检查状态，快照最多每秒常规刷新一次 |
| 正常退出 | stopped，exited=true，ready=false |
| 初始化/运行错误退出 | 保留具体 fault reason 和错误码，exited=true，返回非零 |

空订阅主题记录 `subscription_topic_missing`。进程级致命故障锁存，迟到
回调不能将其覆盖为正常。退出前先撤销就绪，再停止 MQTT 线程和释放资源。
状态初始化失败只记录告警，不阻断原 MQTT 业务；灯控应依赖文件缺失、
身份校验和新鲜度判定不可用。SIGKILL/掉电无法执行退出快照。

旧 `mqtt.state` 的格式和更新逻辑保留。新 JSON 的 ready 表示 broker 连接
及下行订阅就绪，不代表 NS 已收到业务消息。心跳发送不会将新状态强制写成
connected；GPIO1_C1 触发心跳及原 200 ms 限频行为不在本次修改范围。

## 验证方法与结果

在 WSL Ubuntu-22.04 的 MQTT 目录执行；SDK 路径可通过 `SDK_ROOT` 指定：

```sh
python3 -W error::ResourceWarning tests/test_connection_status.py
python3 -W error::ResourceWarning tests/test_main_status.py
bash build_sdk.sh
```

- 现有模块测试：15 项 ARM/QEMU 用例通过，包含 MID、SUBACK、身份、单写者、超时和退出。
- 新增主程序回归：4 组测试，12 个独立主程序场景通过。包含正常生命周期、
  周期刷新、断连、迟到 ACK、重连、broker 拒绝、订阅请求/授予失败、空主题、
  连接/SUBACK 超时、配置/IPC/网络线程启动/epoll 错误及退出原因保留。
- 主程序回归调用生产 `main.c` 的真实主循环和实际注册的回调，使用真实状态
  模块和 GPS 封包；GPIO、IPC、broker 及日志输出均隔离或模拟。可检测再次
  遗漏初始化、回调注册、周期刷新和退出调用的问题。
- GPS 封包和 NS GPS 配置的既有 ARM 测试经 QEMU 执行通过；模拟心跳断言
  `count=32`、`avgsnr=37` 仍正确，且发送心跳不能使断连状态恢复就绪。
- ARM 主程序构建、可执行文件链接成功；保留 3 条原有 strncpy 截断告警。
- 按 CR-at-EOL 规则执行 Git 差异空白检查，适配现有混合行尾。

检查重点：复用状态模块互斥与原子发布，SUBACK MID 关联，停机迟到回调，
错误码在日志调用前保存，未启动的网络线程不执行 loop_stop，未初始化的
Mosquitto 不执行 lib_cleanup；没有新增依赖或输出凭据。
