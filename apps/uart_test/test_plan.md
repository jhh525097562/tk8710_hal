# UART 921600 测试计划（RK3506g）

目标：在 RK3506g 平台上，使用已实现的 UART 节点，以 921600bps 进行高速外设串口通信测试，验证稳定性、吞吐、时延及长期运行表现。

1. 硬件与环境前提
- 外设串口与开发板在 TX↔RX、RX↔TX 正确对接，地线共地。
- 内核驱动和设备树已配置对应 UART 节点，设备节点可访问（如 /dev/ttySx）。
- 如使用 RTOS/裸机混合，请确保在同等条件下测试。此示例在 Linux 用户态下运行。

2. 测试对象与边界
- 波特率：921600，数据位：8，停止位：1，校验位：无，流控：无/RTSCTS。
- 数据模式：连续随机数据、固定模式、循环回环等。
- 测试时长：短时测试（1-5 分钟）、长时测试（≥30 分钟）。

3. 基本用例
- 用例 A：基础通信（8N1，无流控）
  期望：稳定收发，吞吐接近理论值。吞吐目标：≥ 85 KB/s。
- 用例 B：开启硬件流控（RTS/CTS）
  期望：流控正常工作，吞吐稳定，避免丢包。
- 用例 C：错误注入
  端对端注入错误，验证本端错误处理与鲁棒性。
- 用例 D：极限持续传输
  长时间传输，观察内存、缓冲区、系统稳定性。

4. 指标与判定
- 吞吐：单向约 90 KB/s 的理论极限，实际 ≥ 85 KB/s。
- 延迟：单端往返 ≤ 1–5 ms（无额外调度干扰时）。
- 稳定性：长时间（≥ 30 分钟）传输无重大错误或崩溃。
- 数据完整性：通过对比 CRC/校验和，确保无数据丢失。

5. 测试数据与验证方法
- 自环测试：两端直接连接，发送方数据回传，进行比对。
- 端到端测试：使用随机数据，发送端与接收端对比校验。
- 时延测量：记录时间戳，计算单向和往返延迟。
- 日志：记录测试时长、总 TX/RX 字节、吞吐、错误信息。

6. 自动化与报告
- 建议实现一个简单脚本，自动化执行 uart_demo、对端回环、数据校验并输出报告。
- 报告包含：硬件信息、内核版本、测试参数、结果统计、异常情况。

7. 风险与注意
- 某些 RK 系列的 UART 控制器对极高速率支持有限，遇到自带波特率报告不稳定时，请优先使用 115200/230400 等可控速率测试。
- 使用流控时需正确连线 RTS/CTS 引脚，确保不会因为硬件丢失信号而阻塞。
