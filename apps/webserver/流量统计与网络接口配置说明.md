# 流量统计与网络接口配置说明

更新日期：2026-09-20；板端验证：192.168.200.106。

## 流量统计实现

状态页有两套不同含义的网络数据：上方网络状态图通过`/api/traffic`周期采样全部非lo接口的`/proc/net/dev`差值，显示瞬时上传/下载速率；下方流量统计通过`/api/traffic_stats`显示eth0、usb0、wlan0从清零基线开始的累计接收、发送和总量。

旧实现把`/etc/turbotraffic`当成外部服务生成的完整JSON。测试板上该文件和`S39turbotraffic`均不存在，因此API返回`ok=false`，前端一直保留`--`。新实现由Web直接读取内核计数：

```text
/proc/net/dev 当前RX/TX
  - /etc/turbotraffic 对应接口的base_rx/base_tx
  = 页面累计RX/TX，总量为两者之和
```

`/etc/turbotraffic`现在只保存用户点击“清零”时的基线，不是实时流量来源。首次没有文件、JSON损坏时仍显示本次开机累计值。重启或网卡重建使计数回到零时，若当前计数小于旧基线，该方向自动从本次计数重新累计，避免长期显示0。

页面每35秒刷新一次，浏览器切回可见状态后约100ms触发刷新。点击清零后立即重读。未检测到的接口显示“未检测到”；存在但没有流量显示0 B。每项分两行显示总计及接收/发送，避免窄卡片与按钮重叠。

旧`S39turbotraffic`不再是部署依赖，部署检查和文件清单已同步标记废弃。

## Network Interface来源

服务页三个复选框来自Web启动时读取的`/etc/config.json`：

```json
"net_interface": "ETH,WiFi,4G"
```

映射关系：ETH→eth0，WiFi→wlan0，4G→usb0。保存时Web同时更新：

- `/etc/config.json`的`net_interface`，用于页面和应用配置；
- `/etc/tdaemon.conf` `[network]`中的`disabled=`，未勾选接口进入禁用列表。

新配置或缺少配置文件时，默认值已改为`ETH,WiFi,4G`，三项全部选中。已有设备保留其明确保存的选择，不在每次打开页面时强制覆盖；本次按用户要求已在192.168.200.106通过原表单保存为三项全选，守护配置为`disabled=`。

MQTT当前把`net_interface`解析为单一枚举，因此多选字符串在MQTT启动摘要中显示`net=Unknown`；该字段目前只用于这条启动日志。心跳中的`alive.net`由实际默认路由接口检测，板上仍正确上报`eth0`。真正的多网口选路由tdaemon的`disabled`和优先级策略控制。
