# 分类日志导出使用与接口说明

更新日期：2026-09-15。

## 1. 页面操作

登录Web → 系统 → 日志导出。默认选中Web服务、MQTT通信、TK8710网关三类。

1. 勾选日志类型；点“全部类型”选择七类。
2. 列表显示类型、文件名、大小、修改时间，默认选中当前列表全部文件，可逐文件取消。
3. 点击“导出所选日志”；后台准备快照并压缩，页面显示文件处理进度和压缩状态。
4. 完成后点“下载压缩包”，得到 `网关ID_年月日_时分秒_logs.tar.gz`。
5. 解压后按分类目录查看日志，`manifest.json`记录本次选择、源文件、复制字节数及读取结果。

导出不会删除原日志。开始下一次导出会清理上次生成的临时导出包，旧下载链接随之失效。离开页面不会中止后台任务，同一浏览器标签再次进入可查询尚未完成的任务。Web重启后旧任务ID失效，下次导出清理遗留导出目录。

类别没有文件时显示“暂无日志”，其他类别仍能导出。文件在点击导出前已经消失则提示刷新列表；任务开始后消失、轮转或读取失败的文件写入清单并跳过，其他可读文件正常打包。如果所有文件均无法读取，任务返回错误。

## 2. 类型及文件范围

| 类型 | API值 | 来源 |
|---|---|---|
| Web服务 | web | /var/log/web_server.log |
| MQTT通信 | mqtt | /var/log/mqtt_bridge.log |
| TK8710网关 | tk8710 | /userdata/8710log/tk8710_driver_*.log、trm_log_*.log |
| 守护进程 | daemon | /root/daemon_guard.log、/root/tdaemon_debug_full.log |
| 系统日志 | system | /var/log/messages，以及导出时执行dmesg得到的dmesg.txt |
| 升级日志 | upgrade | /tmp/swupdate.log、/userdata/.app-upgrade/last-swupdate.log |
| 业务归档 | business | /userdata/logs/*.dat |

固定名称日志同时识别数字轮转后缀，例如`.1`、`.2`、`.1.gz`，仅纳入实际存在的文件。当前共享日志组件主要保留末尾内容并替换原文件，本功能不会凭空生成历史轮转文件。

按用户要求，没有增加TK8710控制台日志保存，没有修改守护的stdout/stderr重定向。TK8710类型只导出已有Driver/TRM文件；correlation.txt、扫频结果、校准文件和配置文件不在日志导出范围内。

## 3. 后端接口

均位于原有Web鉴权分支，使用现有登录会话；本次没有重做原Web身份认证。

| 方法及路径 | 输入 | 返回 |
|---|---|---|
| GET /api/logs | query types，可用逗号连接类型；省略表示全部 | files、categories、truncated |
| POST /api/log_export/start | JSON types字符串、files文件ID数组 | HTTP202及任务id；并发任务409 |
| GET /api/log_export/status | query id | working/ready/error、completed、total、exported、skipped、filename、message |
| GET /api/log_export/download | query id | ready后返回gzip压缩包，分段发送 |
| GET /api/log_download | 旧接口 | HTTP410，提示刷新页面使用新导出功能 |

开始任务示例：

```json
{
  "types": "web,mqtt,tk8710",
  "files": [
    "web/web_server.log",
    "mqtt/mqtt_bridge.log",
    "tk8710/tk8710_driver_0.log",
    "tk8710/trm_log_0.log"
  ]
}
```

客户端先读列表，再提交其中的ID；不能传任意系统路径。未知类型、重复/无效ID、空选择返回400；超过请求或日志容量限制返回413；空间不足507；不存在或过期的任务404。

列表最大512项，超出时truncated=true，页面提示缩小类型范围。任务最多512个文件、128MiB，dmesg按4MiB预算并限制输出大小。空间预检查要求约两倍日志体积再加16MiB余量，以容纳快照和压缩包。

## 4. 实现位置与处理过程

- `src/log_export.c`、`inc/log_export.h`：类型白名单、枚举、后台线程、文件快照、tar打包、状态与下载。
- `src/web_server.c`：已认证请求的接口路由。
- `web_resources/html/upgrade_logs.html`：分类复选框、文件列表、任务轮询、下载入口。
- `tools/gen_resources.py`：把HTML重新生成到`inc/web_resources.h`；页面内容嵌入可执行文件。
- `tools/test_log_export.py`：明确指定目标板的部署、接口和浏览器测试脚本。

HTTP线程只负责列目录、验证选择及返回状态。实际复制、dmesg采集和tar压缩运行在后台线程，不在HTTP回调里整体读入大文件。下载由Mongoose文件服务分段发送。

同时修复了资源生成器依赖启动目录的问题：SDK从rk3506app目录运行时，原脚本会生成到错误的inc目录，编译仍引用旧页面。现在生成器以自身所在项目为基准定位输入和输出，SDK统一入口与Web目录内Make调用均可更新页面。

暂存目录为`/userdata/.web-log-export/export-XXXXXX/`，权限0700。压缩包只来自本次快照目录；不打包整个userdata。下一次任务仅清理该专用目录中符合生成命名规则的旧任务目录。

读源文件时使用lstat、O_NOFOLLOW及设备号/inode校验，拒绝符号链接或已替换的文件。每个文件只读取任务创建时记录的长度，持续写日志不会导致无限导出。运行中截短记为short_snapshot；这是一组有长度上限的实时快照，不承诺不同程序的日志处于同一个精确时间点。

日常SDK应用编译和预置：

```sh
cd /home/hjh/work/rk3506/rk3506_linux6.1_sdk_v1.2.0
bash external/rk3506app/build_apps.sh --stage
```

源码更新不能改变已生成的SWU/update.img。需要新的升级包时按SWU说明重新制作一个新版本，不覆盖此前已验收的旧发布包。
