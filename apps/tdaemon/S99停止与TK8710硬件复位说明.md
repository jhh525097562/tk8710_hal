# S99tdaemon_job停止与TK8710硬件复位

2026-09-17更新。

## 停止范围

`S99tdaemon_job stop`首先停止tdaemon解释器，再按板端`/etc/tdaemon.conf`所有`proc=`条目强制停止进程。仓库默认配置包含log_daemon、mqtt_bridge、web_server、tk8710_gw和start_frpc.sh。原逻辑采用命令行子串匹配及killall，范围较宽，不能把它用于仅停止一个业务进程。

start_frpc.sh被SIGKILL时无法执行清理trap，所以其frpc子进程不保证一起退出；本次保留既有行为，不宣称停止全部FRP进程。SSH服务本身不在默认列表，但停止Web会断开Web访问，远程维护应谨慎。

## 新增停止时序

1. 停止tdaemon，避免自动拉起业务。
2. 强制停止配置列表中的进程，并兜底停止手动启动的tk8710_gw。
3. 最多等待5秒确认没有tk8710_gw进程；如果仍存在，拒绝复位并返回失败。
4. 执行`/usr/bin/tk8710_reset`：申请gpiochip0的line13（GPIO0_B5）为低电平，保持至少10ms，再设置高电平并释放GPIO。
5. 成功才打印`OK (TK8710 hardware reset completed)`。复位工具缺失或GPIO操作失败时stop返回非零；restart不会继续start。

该时序对应HAL中`TK8710HardwareResetPulse()`，不包含重新初始化芯片，不是持续保持复位或关闭芯片电源。释放GPIO后的长期电平还依赖GPIO控制器/板级上下拉，不能仅凭工具退出0认定射频物理停发已验收。

`tk8710_reset.c`使用现有libgpiod 1.x API，同一次申请内完成整个脉冲。不要在业务运行期间单独执行它。

本次只修改S99的stop/restart路径；配置变化导致的kill、异常退出及SWU内部停止逻辑没有自动加入这一动作，后续若要覆盖这些路径需单独接入。

## SDK和部署

本地与SDK external/rk3506app/tdaemon已同步；SDK overlay预置：

- `/etc/init.d/S99tdaemon_job`
- `/usr/bin/tk8710_reset`

`build_apps.sh --stage`已加入复位工具编译、二进制及S99脚本预置，两者必须配套部署。只更新S99而缺少工具会报失败。更改位于rootfs，不在旧三App SWU覆盖范围中。

如果板端inittab另有tdaemon的respawn条目，直接stop可能被init重新拉起，需先处理该外部监督入口；本脚本不负责修改inittab。人工同时启动TK8710也不在停止流程的并发保证范围内。

## 验证

- sh -n检查通过。
- ARM工具链以-Wall -Wextra -Werror编译通过。
- test_stop_reset.py模拟验证低电平、10ms、高电平的顺序，GPIO失败非零退出，进程未退出时禁止复位，以及restart遇到stop失败时停止。
- 未在板上执行stop或GPIO复位，未用示波器确认脉冲/射频停发，也未重新生成完整固件。

板级验收应在明确维护窗口进行：确认正确板型/引脚 → 运行stop → 确认tk8710_gw退出、复位工具成功 → 示波器验证低脉冲及释放电平 → 检查芯片/射频确实停止原业务 → start后验证重新初始化。
