# RK3506 App 逻辑错误与风险审查报告

## 1. 风险汇总表

| 模块及功能 | 严重程度 | 问题 | 后果 | 如何修改 | 修改风险 |
| --- | --- | --- | --- | --- | --- |
| `web_server`：Web 管理后台，负责登录、配置、升级、RF、日志页面/API。 | 严重/高 | 固定 Cookie 可绕过登录；页面输出未统一转义；状态变更接口缺少 CSRF。 | 可直接访问管理 API；管理员可能被 XSS/CSRF 诱导改配置、升级或重启。 | 随机 session；统一 HTML 转义；所有 POST 增加 CSRF token。 | 登录、表单、AJAX、调试工具都要适配。 |
| `network_manager`：Web 网络配置和 ping 诊断。 | 严重 | ping 参数可命令注入；网络配置参数可注入 `/etc/network/interfaces`。 | 可执行任意命令；可能写坏网络配置或注入网络脚本指令。 | ping 不走 shell；IP/域名/proto 白名单校验；拒绝换行和控制字符。 | 代码复杂度增加，历史脏配置可能保存失败。 |
| `upgrade_manager`：Web 固件上传并调用 `swupdate`。 | 严重 | 固件固定写 `/tmp/image.swu`，缺少完整性、并发和 symlink 防护。 | 可能覆盖文件、安装旧包/半包，导致升级失败或设备异常。 | 私有上传目录；禁止 symlink；增加上传会话、大小、hash/签名校验。 | 前端上传流程和存储路径要同步调整。 |
| `ipc_smp`：MQTT 与 SPI/TK8710 之间的共享内存 IPC。 | 严重 | ring wrap 空间计算少算 padding；接收端信任共享内存 header 长度。 | 可能覆盖未读 IPC 数据；损坏共享内存可能导致越界读或崩溃。 | 校验真实可用空间；校验 version、type、len、rec_size 和 mmap 边界。 | 修复后会暴露上层流控问题；旧共享内存可能需清理。 |
| `mqtt_bridge`：连接 MQTT 云端，转发 NS 下行和 SPI 上行。 | 高 | publish 失败仍 ACK；配置未送 SPI 就标记收到；payload_len 未校验；多线程状态无锁；连接状态和心跳范围处理不严；未启用 TLS。 | 上行数据永久丢失；SPI 可能拿不到配置；可能越界读；LED 误报；账号和业务数据明文暴露。 | publish 成功后 ACK；配置发送成功后置位；校验 payload_len；共享状态加锁；限制心跳；增加 TLS。 | 队列可能堆积；两端协议可能要同步；TLS 证书和旧 Broker 要兼容。 |
| `mac_msg_parser`：MQTT JSON、Base64 和协议字段解析。 | 高 | Base64 解码失败仍可能转空 payload；`rate_num` 等字段未严格限幅。 | 非法下行被当合法包转发；可能越界读或下发非法硬件配置。 | 解码失败直接丢弃；限制 `rate_num <= MAX_RATE_CFGS`；校验频点、slot、rate。 | 服务端非标准或超限报文会被拒绝。 |
| SPI/TK8710 侧进程：消费下行并连接硬件。 | 高 | 当前 SPI 代码疑似模拟逻辑，SPI 打不开也继续运行。 | 若用于生产，下行不会真实写硬件，上行可能是假数据。 | 生产/模拟分离，生产模式 SPI 失败直接退出。 | 调试环境需要显式模拟参数。 |
| `tdaemon`：进程守护、网络检测和恢复。 | 高 | 无网超时强制重启；进程判断偏宽松；多个脚本覆盖 DNS。 | ICMP 被屏蔽或 AP 配网时可能重启循环；同名进程误判；DNS 被覆盖。 | 无网重启加退避/默认关闭；精确匹配进程；统一 DNS 管理。 | 真实死网恢复可能变慢；BusyBox 兼容需验证。 |
| Wi-Fi 脚本：wlan0 AP/STA 切换。 | 高 | 全局 `killall/pkill` 杀网络进程；锁文件有竞态。 | 可能误杀 eth0/4G DHCP；多个实例并发切换导致 Wi-Fi 不稳定。 | 只杀 wlan0 相关 PID；锁文件不截断，拿锁后写 PID。 | 旧残留进程和 stale lock 需要单独处理。 |
| `log_daemon`：UDP 日志接收和落盘。 | 高 | 启动参数无范围校验。 | `max_file=0` 等异常参数可导致日志进程死循环。 | 用 `strtol` 校验 port、ring、flush、文件大小等范围。 | 旧错误配置会被拒绝启动。 |
| `lan_discoveryd`：UDP 局域网发现。 | 高 | `gateway_id` 拷贝可能没有字符串结尾。 | 超长配置可能导致越界读、崩溃或泄露栈数据。 | 用 `snprintf`，并限制 `gateway_id` 长度。 | 超长 ID 会被截断或拒绝。 |
| `config_manager`：读写 `/etc/config.json`。 | 高 | 密码明文保存；配置文件非原子写。 | 凭据泄露；断电可能写坏配置导致业务启动失败。 | 密码 hash/权限 0600；临时文件+fsync+rename 原子写。 | 旧配置需要迁移，需实机验证文件系统行为。 |

## 2. 修复优先级表

| 优先级 | 先修内容 | 原因 |
| --- | --- | --- |
| P0 | Web 认证、ping 命令注入、网络配置注入、固件上传路径。 | 都是管理入口高危问题，可能直接控制设备。 |
| P1 | `ipc_smp` wrap/header、MQTT ACK、payload_len、Base64、配置 ACK。 | 影响核心数据链路，可能损坏数据或静默丢数据。 |
| P2 | MQTT 线程同步、连接状态、心跳范围、TLS。 | 提升稳定性和通信安全。 |
| P3 | `tdaemon` 重启策略、Wi-Fi kill/锁、进程匹配、DNS 管理。 | 降低现场断网、误重启和维护风险。 |
| P4 | 配置原子写、日志参数校验、Discovery 字符串安全。 | 提高系统健壮性。 |

## 3. 修改风险表

| 修改类型 | 风险 | 控制办法 |
| --- | --- | --- |
| Web 安全加固 | 登录、上传、表单流程会变化。 | 前端、curl、产测工具同步适配。 |
| IPC/协议修复 | MQTT 和 SPI 两端协议不一致会断链。 | 两端同步升级，加协议版本。 |
| ACK/重试策略 | MQTT 断网时本地队列可能堆满。 | 设置缓存上限、丢弃策略和统计告警。 |
| 文件原子写 | 不同文件系统行为可能不同。 | 在 RK3506 实机验证断电、空间不足、只读场景。 |
| 守护脚本修改 | 网络恢复策略变化可能影响现场恢复。 | 分阶段灰度，保留手动恢复入口。 |
| TLS 引入 | 证书、时间同步、旧 Broker 兼容复杂。 | 先做可配置 TLS，再逐步默认启用。 |
