# 独立唤醒信号发送测试

入口：`Test8710Wakeup.c`。参考 `Test8710RFTest.c` 的初始化和
`TK8710Ctrl(TK8710_CTRL_TYPE_SEND_WAKEUP, ...)` 流程。

## 编译

在已配置交叉工具链的 Linux/WSL 中，从仓库根目录执行：

```bash
source ~/arm-buildroot-linux-gnueabihf_sdk-buildroot/environment-setup
bash cmake/build_rk3506.sh Test8710Wakeup
```

如果 Windows 检出导致脚本为 CRLF 换行，可只在执行时转换：

```bash
tr -d '\r' < cmake/build_rk3506.sh | bash -s -- Test8710Wakeup
```

输出为 `build_rk3506/Test8710Wakeup`，构建脚本自动发现此入口。

## RK3506 上运行

将程序放到板子 `/userdata` 后，在板子的终端执行：

```bash
cd /userdata
chmod +x Test8710Wakeup
./Test8710Wakeup --help
./Test8710Wakeup MODE FREQUENCY_HZ DURATION_MS REG0814 REG0824
```

最后一行是参数模板，需替换全部大写占位符：

| 参数 | 含义 | 范围或示例 |
|---|---|---|
| MODE | 唤醒模式 | 1～3，例如 2 |
| FREQUENCY_HZ | RF 频率，单位 Hz | 非零 uint32，例如 509100000；与接收端匹配 |
| DURATION_MS | 唤醒信号时长，单位 ms | 0～16777215，例如 5000；初测建议非零 |
| REG0814 | 全局寄存器 0x0814 的完整 32 位值 | 由测试方案指定，支持十进制、0x 十六进制 |
| REG0824 | 全局寄存器 0x0824 的完整 32 位值 | 由测试方案指定，支持十进制、0x 十六进制 |

例如，模式 2、509.1 MHz、5000 ms 的命令模板为：

```bash
./Test8710Wakeup 2 509100000 5000 REG0814 REG0824
```

两个寄存器值必须按实际测试要求替换，程序不猜测默认值。输入的是整寄存器值，
程序直接原样写入，不移位、不按位合并，也不写其他通道的同偏移地址。

## 执行行为

1. 校验所有参数，非法参数在访问硬件之前退出。
2. 按原 RF 测试程序初始化 TK8710 和 RF，TX 增益固定 0x2A、RX 增益固定 0x7E。
3. 初始化后依次写入、读回 0x0814 和 0x0824。初始化本身会写 0x0814，
   所以自定义值必须在初始化后覆盖。读写失败或读回不一致时退出，不触发本次发送。
4. 下发唤醒发送配置，wakeUpId 固定为 0。时长计时由芯片完成，程序保留在交互界面。
5. 输入 `u` 并回车：重新应用两个寄存器值并重发同一配置。
   请等待前次发送完成再重发，程序不检测芯片忙状态。
6. 输入 `q` 并回车或标准输入 EOF：退出进程。退出不额外下发停止或复位，
   不将进程退出当作停止发射命令；正常测试请等待配置时长结束后退出。

`Wakeup configured` 只表示驱动配置调用成功。实际 RF 波形、持续时长和接收端唤醒
结果需要在板子及仪表上验证；频率参数的合法 RF 频段也需按实际射频硬件选择。
