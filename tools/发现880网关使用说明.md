# 880 网关发现工具使用说明

`发现880网关.ps1` 用于在 Windows 电脑上发现可通过局域网访问的 880 网关。
当已知网关所在的 IPv4 网段时，建议显式传入该网段，让工具在广播发现之外，
再逐个地址发送单播发现请求。

> 说明：这里需要的是局域网“网段”，不是无线“频段”。例如，已知网关地址位于
> `192.168.10.x`、子网掩码为 `255.255.255.0`，对应网段为
> `192.168.10.0/24`。

## 1. 使用条件

运行前确认：

- 使用 Windows PowerShell 或 Windows 上的 PowerShell 7；
- 电脑已接入网关所在局域网，或电脑到目标网段已有可用路由；
- 网关上的 `lan_discoveryd` 服务正在运行；
- 网络和防火墙允许向网关 UDP `20165` 端口发送报文，并允许响应报文返回；
- 已知目标网段及其 CIDR 前缀，例如 `192.168.10.0/24`。

常见子网掩码与 CIDR 的对应关系：

| 子网掩码 | CIDR | 网段示例 |
| --- | --- | --- |
| `255.255.255.0` | `/24` | `192.168.10.0/24` |
| `255.255.0.0` | `/16` | `192.168.0.0/16` |
| `255.255.255.128` | `/25` | `192.168.10.0/25` 或 `192.168.10.128/25` |

工具默认最多扫描 4096 个主机地址。`/24` 包含 254 个常规可用主机地址，
适合直接扫描；`/16` 范围过大，默认会被工具拒绝，应先缩小到实际子网，
不建议直接提高上限扫描整个 `/16`。

## 2. 最快使用方法

以下示例假设：

- 工具路径为 `D:\CodexWorkSpace\tk8710_hal_v1.6\tools\发现880网关.ps1`；
- 已知网关位于 `192.168.10.x`；
- 子网掩码为 `255.255.255.0`；
- 因此目标网段为 `192.168.10.0/24`。

打开 PowerShell，执行：

```powershell
Set-Location 'D:\CodexWorkSpace\tk8710_hal_v1.6'
& '.\tools\发现880网关.ps1' -ScanSubnets @('192.168.10.0/24')
```

如果系统提示禁止运行脚本，可只为当前 PowerShell 进程临时放开执行策略，
关闭该窗口后设置即失效：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
& '.\tools\发现880网关.ps1' -ScanSubnets @('192.168.10.0/24')
```

也可以从 CMD 或“运行”窗口一次性调用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\CodexWorkSpace\tk8710_hal_v1.6\tools\发现880网关.ps1" -ScanSubnets "192.168.10.0/24"
```

## 3. 根据已知网段进行扫描

### 3.1 一个网段

网关可能位于 `192.168.100.x/24`：

```powershell
& '.\tools\发现880网关.ps1' -ScanSubnets @('192.168.100.0/24')
```

### 3.2 多个候选网段

不确定网关位于 `192.168.100.x` 还是 `192.168.200.x` 时：

```powershell
& '.\tools\发现880网关.ps1' `
    -ScanSubnets @('192.168.100.0/24', '192.168.200.0/24')
```

### 3.3 调整等待时间和重试次数

网络较慢或容易丢包时，可增加广播重试次数和每轮接收等待时间：

```powershell
& '.\tools\发现880网关.ps1' `
    -ScanSubnets @('192.168.10.0/24') `
    -Retries 5 `
    -TimeoutSeconds 5
```

`Retries` 只控制每个本机网卡的广播发送次数；指定网段的单播扫描会向每个主机
地址发送一次请求，然后在 `TimeoutSeconds` 指定的时间内等待回复。

### 3.4 使用非默认发现端口

只有当网关端发现服务已改用其他端口时，才需要设置 `ListenPort`：

```powershell
& '.\tools\发现880网关.ps1' `
    -ScanSubnets @('192.168.10.0/24') `
    -ListenPort 20165
```

默认端口就是 UDP `20165`。

## 4. 工具的发现过程

工具会按以下顺序执行：

1. 枚举电脑上所有状态正常的 IPv4 地址，排除回环地址和 `169.254.x.x` 地址；
2. 从每个可用网卡向该网卡的定向广播地址和 `255.255.255.255` 发送发现请求；
3. 对 `ScanSubnets` 中的每个网段逐个主机地址发送单播发现请求；
4. 接收并解析网关返回的 `discovery_rsp`；
5. 按网关 ID、MAC 或响应源 IP 去重后，以表格形式显示结果。

未指定 `ScanSubnets` 时，脚本默认扫描：

- `192.168.100.0/24`
- `192.168.200.0/24`

如果已知网关所在网段，应显式传入 `-ScanSubnets`，覆盖上述默认值，减少无关扫描。

## 5. 如何查看结果

发现成功时，工具会输出类似结果：

```text
Discovered 1 gateway(s):

GatewayId       ReportedIP      SourceIP       MAC                ActiveInterface ReceivedVia
---------       ----------      --------       ---                --------------- -----------
880-XXXXXXXX    192.168.10.25   192.168.10.25  AA:BB:CC:DD:EE:FF eth0            route:192.168.10.0/24
```

各字段含义：

| 字段 | 含义 |
| --- | --- |
| `GatewayId` | 网关上报的网关 ID（`gwid`） |
| `ReportedIP` | 网关在响应内容中上报的 IP 地址 |
| `SourceIP` | 电脑实际收到 UDP 响应时看到的源 IP 地址 |
| `MAC` | 网关上报的 MAC 地址 |
| `ActiveInterface` | 网关上报的当前活动网络接口 |
| `ReceivedVia` | 发现路径；本机 IP 表示广播发现，`route:网段` 表示指定网段的单播发现 |

通常可优先使用 `SourceIP` 访问网关。如果 `ReportedIP` 与 `SourceIP` 不一致，
可能存在多网卡、NAT、网关配置未刷新等情况，应结合 `ActiveInterface` 检查。

发现成功时脚本退出码为 `0`；没有发现网关时退出码为 `1`。

## 6. 没有发现网关时的排查顺序

如果显示 `No 880 gateway was discovered.`，按以下顺序检查：

1. **确认网段写法正确**

   例如网关地址为 `192.168.10.25`、掩码为 `255.255.255.0`，建议传入规范的
   网络地址 `192.168.10.0/24`。工具也能根据 `192.168.10.25/24` 计算扫描范围，
   但使用网络地址更容易核对且不易混淆。

2. **确认电脑有到目标网段的连接或路由**

   执行以下命令查看电脑的 IPv4 地址和默认网关：

   ```powershell
   Get-NetIPConfiguration
   ```

   跨网段扫描时，路由器必须允许电脑向目标网段发送单播 UDP 报文，并允许响应返回。
   普通路由器通常不会转发广播，因此跨网段场景主要依赖工具的单播扫描。

3. **确认网关发现服务和端口**

   网关上的 `lan_discoveryd` 必须正在运行并监听 UDP `20165`。如果服务端端口已改动，
   使用相同的 `-ListenPort` 参数运行本工具。

4. **检查 Windows 和网络防火墙**

   确认 `powershell.exe` 或 `pwsh.exe` 可以发送 UDP 请求并接收返回报文；同时确认交换机、
   路由器或安全软件没有拦截 UDP `20165` 以及返回流量。

5. **增加等待时间后重试**

   ```powershell
   & '.\tools\发现880网关.ps1' `
       -ScanSubnets @('192.168.10.0/24') `
       -Retries 5 `
       -TimeoutSeconds 10
   ```

6. **检查扫描规模限制**

   如果提示 `contains ... hosts; limit is 4096`，说明目标 CIDR 过大。优先确认并缩小实际
   子网。只有明确需要扫描更大范围时，才使用 `-MaxUnicastHosts` 提高上限，例如：

   ```powershell
   & '.\tools\发现880网关.ps1' `
       -ScanSubnets @('192.168.0.0/19') `
       -MaxUnicastHosts 8190
   ```

## 7. 参数说明

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `ListenPort` | `20165` | 网关发现服务的 UDP 目标端口 |
| `TimeoutSeconds` | `3` | 每个广播网卡和每个单播网段发送完成后的接收等待时间 |
| `Retries` | `3` | 每个本机 IPv4 接口的广播发现重试次数 |
| `ScanSubnets` | `192.168.100.0/24`、`192.168.200.0/24` | 需要逐地址扫描的 IPv4 CIDR 网段 |
| `MaxUnicastHosts` | `4096` | 每个单播网段允许扫描的最大主机地址数 |

## 8. 推荐命令模板

将下面的 `<目标网段>` 替换为实际网段即可：

```powershell
Set-Location 'D:\CodexWorkSpace\tk8710_hal_v1.6'
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
& '.\tools\发现880网关.ps1' `
    -ScanSubnets @('<目标网段>') `
    -TimeoutSeconds 5 `
    -Retries 3
```

例如目标网段为 `10.10.20.0/24`：

```powershell
& '.\tools\发现880网关.ps1' -ScanSubnets @('10.10.20.0/24')
```
