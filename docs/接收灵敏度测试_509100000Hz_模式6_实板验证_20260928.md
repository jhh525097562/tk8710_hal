# 接收灵敏度模式实板验证（2026-09-28）

## 结论

最新应用已通过 XDS100v2 烧录并读回校验。在用户已连接并发送测试数据的信号源条件下，TK8710 速率 6、509100000 Hz、工作模式 7 接收正常。两组完整的 100 窗口统计均无失败，累计 200 个窗口、200 个有效用户。该结果验证当前输入条件下的接收功能，不等于测得接收灵敏度门限。

## 实测证据

主验证记录：`reports/rx_sensitivity/20260928_174141.log`。在启动和查询阶段也持续收集串口，专门等待接收的时间为 60 秒，完整日志共记录 259 条有效用户日志。

| 项目 | 结果 |
|---|---|
| 启动参数 | `freq=509100000 rate=6 S3=69536 bytes=22` |
| 前后工作状态 | `STATE=RUNNING MODE=7` |
| 第 100 窗口 | `windows=100 lost=0 last100Lost=0 validUsers=100` |
| 第 200 窗口 | `windows=200 lost=0 last100Lost=0 validUsers=200` |
| 遥测接收数 | 从 27 增至 240，两次快照间隔 67 秒 |
| SPI 错误 | 两次快照均为 `spiErr=0` |
| 最近用户日志 | user=0，RSSI=-104..-103，SNR=53，频率偏移读数=20126 Hz |

RSSI/SNR 为软件按参考程序公式换算后的读数，未进行功率计校准；频率读数包含测试配置中的频率偏置，不应直接作为晶振误差。窗口失败率仅涵盖产生 MD_DATA 中断的窗口，不能代替信号源发送计数分母下的端到端丢包率。

退出/重新进入验证也通过，记录为 `reports/rx_sensitivity/20260928_174334.log`：`AT+STOP` 成功后重新设置参数并进入模式 7；`configVersion=3`、`lastResult=0`，两次遥测 rx 从 28 增至 66，SPI 错误始终为 0。测试结束保持 `RUNNING / MODE=7`，频率 509100000 Hz、速率 6，采集程序退出并释放 COM22，便于继续现场测试。

## 本次发现并修正的问题

首次实板运行在初始化 ACM auto-gain 阶段进入 Data Abort：PC 曾停在异常向量 0x10，异常模式 CPSR=0x40000397、LR=0x54D22，尚无接收窗口。反汇编对应运行库栈恢复指令附近；当前应用任务栈为 4 KiB，新增初始化函数局部配置占用约 516 字节栈帧（另有保存寄存器）。

将灵敏度初始化使用的 slotCfg、ChipConfig 和回调配置改为静态存储后，重新编译、烧录，初始化及持续接收恢复正常。模式切换由主循环串行执行，静态配置不引入并发调用。该复测支持栈空间压力判断；未使用故障地址寄存器证明精确的栈越界地址。主机 `rx_sensitivity_test` 在修正后再次通过。

首次失败记录：`reports/rx_sensitivity/20260928_173528.log`；调试记录：`reports/rx_sensitivity_inspect_detail.log`；最终烧录记录：`reports/rx_sensitivity_flash_fixed_20260928.log`。

## 限制和后续测量

信号源输出功率、线损和灵敏度判定的目标误包率未提供，本次没有调节信号源或测量灵敏度极限。ADC 启动时仍有通道映射告警，此项不是本次接收测试的通过项目。

同步说明修正：参考程序及本模式的 `slotCfg.local_sync` 均为 0，但当前仓库 Driver 没有使用该结构字段；不能仅凭字段注释或启动日志的 `externalSync=1` 就断言现场必须额外提供同步脉冲。本次是在用户现有连接与信号源波形条件下实际收到了数据。
