# RK3506 外部 PPS UART 管理功能概要设计

**版本：** V1.0
**日期：** 2026-09-02

# 1. 设计目标

提供与现有 HAL 生命周期解耦、可复用和可诊断的外部 PPS 管理模块，并提供能够长期运行和自动恢复的 RK3506 板端测试程序。

# 2. 总体方案

新增公共头文件和实现模块。模块持有 UART 文件描述符及配置，负责行协议传输、响应分类和字段解析；复位复用已有 `TK8710GpioSet()`。测试程序在 API 之上实现监控与恢复策略，不把测试策略固化进底层通信 API。

# 3. 模块划分

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| PPS 公共 API | 生命周期、命令、结构化状态、诊断、复位 | 不决定业务复位阈值 |
| UART 协议实现 | termios、poll、按行分帧、OK/ERR/EVENT 分类、KV 解析 | 不解释物理波形 |
| GPIO 复位适配 | 拉低、延时、拉高和 UART 重连 | 复用 RK3506 port API |
| PPS 测试程序 | 固定 10 秒配置、健康状态机、诊断、限流恢复、信号退出 | 不修改主 HAL 生命周期 |
| 构建集成 | 将库源和示例目标加入 RK3506 构建 | JTOOL 不实现 UART |

# 4. 功能设计

| 功能 ID | 功能 | 输入 | 输出 |
| --- | --- | --- | --- |
| F-01 | 设备连接 | 串口及超时配置 | 上下文或错误码 |
| F-02 | 输出控制 | enable | AG32 确认 |
| F-03 | 周期配置/读取 | 周期秒数 | 当前及待生效状态 |
| F-04 | 状态与健康判定 | `GET STATUS` | 结构化状态和判定结果 |
| F-05 | 诊断采集 | 五个 GET 命令 | 原始分项响应集合 |
| F-06 | 设备复位 | GPIO 配置 | 复位并重连结果 |
| F-07 | 长期监控 | 固定运行参数 | 日志、恢复或失败退出 |

# 5. 工作流程设计

## 5.1 正常流程

1. 初始化配置并确保复位 GPIO 为高电平。
2. 打开 UART，记录 `GET VERSION` 和初始 `GET STATUS`。
3. 严格发送 `OUT ON`，成功后发送 `SET PERIOD 10`。
4. 在 60 秒启动宽限内每 2 秒读取状态，等待周期生效和对齐。
5. 进入健康态后持续轮询。

## 5.2 命令交互

每次只允许一个在途命令。发送 LF 结尾命令后，接收器逐行处理：`EVENT` 记录但继续等待；匹配的 `OK` 完成本次调用；`ERR` 返回协议错误；超时或 I/O 错误返回相应错误码。

## 5.3 异常与恢复

1. 串口连续失败 3 次，或启动 60 秒仍未健康，或健康后连续 3 次异常，进入诊断阶段。
2. 尽可能采集五项详细诊断；诊断失败不阻止硬件恢复。
3. 满足 30 秒复位冷却后，GPIO 拉低 100 ms，再恢复高电平。
4. 等待配置的启动时间，重开 UART。
5. 严格执行 `OUT ON`、`SET PERIOD 10`，清零本轮连续异常计数并重新进入启动宽限。
6. 连续三轮恢复仍失败则退出。

# 6. 数据与边界概览

核心对象包括设备配置、设备上下文、周期信息、运行状态、诊断结果和健康枚举。所有数值使用 `<stdint.h>` 定宽类型；字符串使用固定长度数组，不暴露内部 UART 缓冲区。

# 7. 技术选型与权衡

| 决策 | 选择 | 备选 | 理由 |
| --- | --- | --- | --- |
| API 边界 | 独立公共模块 | 并入 `hal_api.h` | 避免外设生命周期污染 TK8710 HAL |
| 串口实现 | POSIX termios + poll | 第三方串口库 | 与现有 `uart_test.c` 和目标系统一致，无新增依赖 |
| GPIO | 复用 `TK8710GpioSet` | 启动 `gpioset` 子进程 | 避免 shell 依赖并获得明确返回码 |
| 诊断结构 | 结构化状态 + 原始诊断文本 | 单一健康布尔值 | 兼顾稳定 API 和协议排障信息 |
| 自动恢复 | 测试程序策略 | 底层 API 自动复位 | 调用者可控，避免隐式硬件副作用 |

依据为仓库现有 RK3506 port、构建脚本及 `3506uart/串口协议使用文档.md`。不引入新框架，无需单独 ADR。

# 9. V1.1 网关 GPS/PPS 集成

网关在 IPC 和 TK8710 初始化前独立探测 AG32。模块不存在时立即选择本地同步；模块存在时等待最多 300 秒获得基础 GPS 信号。只有正常 NS 配置产生了合法的整数秒时隙周期，并且 AG32 按 `OUT ON`、`SET PERIOD` 完成对齐后，TK8710 才选择外部同步。

运行期每 10 秒查询一次。外部同步连续 3 次完整健康检查失败时统一清理并返回 1；GPS 搜星或配置失败后的本地降级模式中，基础 GPS 信号连续 3 次恢复时返回 2，请求保护进程重新拉起。默认配置和扫频没有时隙计算器结果，固定使用本地同步且不触发 GPS 恢复退出。

同步模式通过 `slotCfg_t.local_sync` 传递。普通启动与 ACM 快速启动共享同一个寄存器辅助函数：本地同步写入 `ls_en=0、ls_master=1`，外部同步写入 `ls_en=1、ls_master=0`。外部同步 ACM 完成后立即触发快速启动，由硬件等待下一次外部 PPS；本地同步保留原精确时间等待与相位监控。
