# ACM周期计时溢出修复（2026-09-24）

现象为60分钟周期校准后约11分35秒再次请求校准。RK3506原实现
`(uint64_t)(tv.tv_sec * 1000000 + tv.tv_usec)`在32位乘加后才扩展，
微秒结果每4294.967296秒重复；符号边界使无符号时间差异常放大。

本次修复：

- RK3506的TK8710GetTimeUs保留原日历时钟语义，但在乘法之前扩展到64位。
- 新增平台接口TK8710GetMonotonicTimeUs；RK3506使用CLOCK_MONOTONIC，Windows
  JTOOL使用QueryPerformanceCounter。读取失败返回0。
- TRM初始化及周期请求检查统一使用单调时钟，禁止混用两种时间基准。
- 差值判断先排除0和时间倒退，再做无符号减法；只有请求成功才更新上次请求时间。
- 默认周期仍为60分钟。周期日志新增monotonic_us与elapsed_us，应满足
  elapsed_us >= 3600000000；实际校准仍可能等待PPS周期末帧。
- 校准因子文件继续按系统日历时间记录，不改变已有时间格式。

验证：主机测试覆盖有符号/无符号32位回绕点、日历大数值、六小时模拟计时、
60分钟边界、11分35秒不触发及倒退/失败读数；原ACM/PPS模型回归通过。
完整RK3506网关编译链接及JTOOL源文件语法检查通过。
