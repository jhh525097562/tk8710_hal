# TRM卫星载荷/地面站测试项目清单

版本：v0.1  
日期：2026-06-24  
依据：`docs/TurMass卫星物联网演示验证方案-v0.3.md` 第 9 章

## 1 测试目标

验证 TRM 在三类节点角色下的行为满足卫星物联网演示验证方案第 9 章要求：

| 角色 | 测试目标 |
| ---- | -------- |
| 地面网关 | 默认角色行为保持兼容，现有地面网关业务不受卫星功能影响 |
| 卫星载荷 | 解析卫星 MAC 帧，维护终端波束、地面站波束、终端到地面站路由和终端上行缓存，并按时隙转发完整 MAC 包 |
| 卫星地面站 | 扫描 BCN，入网维持，接收卫星转发终端数据，维护终端波束，并把服务器下行响应转发给卫星 |

## 2 测试环境与程序

| 项目 | 内容 |
| ---- | ---- |
| 卫星载荷程序 | `test/example/tk8710_gw_sat.c`，TRM 角色为 `TRM_NODE_ROLE_SAT_PAYLOAD` |
| 地面站程序 | `test/example/tk8710_gw_ground.c`，TRM 角色为 `TRM_NODE_ROLE_GROUND_STATION` |
| 默认地面网关程序 | 现有 `tk8710_gw` 或未配置卫星角色的 TRM/HAL 初始化路径 |

| 关键日志 | `TRM SAT: rx role=...`、`ground-station beam update`、`route update`、`terminal uplink queued`、`cache terminal uplink`、`downlink response queued`、`ground-station tx freq hop`、`TRM: User ID[...] freq = ...` |

## 3 测试状态定义

| 状态 | 含义 |
| ---- | ---- |
| 待测 | 尚未完成现场验证 |
| 需复测 | 相关代码或解析规则近期调整，必须重新跑现场验证 |
| 已初验 | 单次或少量日志已证明主路径可通，但还缺少重复次数、边界或统计 |
| 通过 | 已按验收标准完成并记录日志 |
| 阻塞 | 环境、依赖库、硬件链路或服务器未就绪导致无法执行 |

## 4 P0 必测项目

### P0-01 角色配置和默认兼容性

| 项目 | 内容 |
| ---- | ---- |
| 目的 | 确认 `TRM_InitConfig.nodeRole` / `TK8710HalTrmCfg.nodeRole` 正确生效，未配置时默认保持地面网关行为 |
| 步骤 | 分别启动默认地面网关、卫星载荷、地面站程序；检查初始化日志和 TRM 角色 |
| 验收 | 默认角色为 `GROUND_GATEWAY`；卫星载荷日志显示 `role=1`；地面站日志显示 `role=2`；现有地面网关收发回归正常 |
| 状态 | 待测 |

### P0-02 MAC 字段解析复测

| 项目 | 内容 |
| ---- | ---- |
| 目的 | 验证卫星 TRM 只解析 MHDR、DevType、NwkMode、FrameType、Src Addr/DevEUI，不解析应用 payload |
| 步骤 | 构造或现场发送卫星网络 Data、Join Request、Join Accept 帧，检查 TRM 日志解析结果 |
| 验收 | Data 帧从 FHDR `data[3..6]` 提取 `Src Addr`；Join Request 跳过 `Capacity`，从 `data[4..11]` 的 DevEUI 提取终端/地面站 ID；Join Accept 跳过 `JoinResult`，从 `data[4..11]` 的 DevEUI 提取目标 ID；非卫星网络帧不触发卫星转发 |
| 状态 | 需复测 |

### P0-03 地面站 BCN 扫描和入网流程

| 项目 | 内容 |
| ---- | ---- |
| 目的 | 验证地面站连续收到有效 BCN 后发送入网请求，卫星载荷回复入网响应 |
| 步骤 | 启动卫星载荷广播 BCN；启动地面站；观察连续 BCN、入网请求入队、卫星载荷收到入网请求、回复入网响应、地面站 online 日志 |
| 验收 | 地面站连续 2 帧 BCN 正确后发送 Join Request；卫星载荷更新该地面站波束并发送 Join Accept；地面站收到 Join Accept 后进入 online |
| 状态 | 已初验，需重复统计 |

### P0-04 地面站入网维持周期

| 项目 | 内容 |
| ---- | ---- |
| 目的 | 验证地面站不新增心跳帧，使用入网请求帧维持在线和波束 |
| 步骤 | 地面站 online 后保持空闲，观察 1 分钟维持重发；期间插入一次业务下行，再观察计时基准是否按最后一次向卫星发送时间刷新 |
| 验收 | 空闲约 `groundStationJoinMaintainMs` 后重发 Join Request；若期间发送业务数据，则维持计时从业务发送时间重新计算；未收到 Join Accept 时按入网超时重试 |
| 状态 | 待测 |

### P0-05 卫星载荷地面站波束维护

| 项目 | 内容 |
| ---- | ---- |
| 目的 | 验证卫星载荷维护最多 5 个地面站波束，并按最新有效地面站波束转发终端上行 |
| 步骤 | 让 1 个或多个地面站发送 Join Request；再让终端发送上行数据；观察地面站波束新增、更新、选择和转发日志 |
| 验收 | 同一地面站地址重复入网只更新不新增；最多维护 5 个地面站波束；终端上行转发选择最近更新且未超时的地面站波束 |
| 状态 | 已初验单地面站，多地面站待测 |

### P0-06 地面站波束超时

| 项目 | 内容 |
| ---- | ---- |
| 目的 | 验证地面站波束失效逻辑与地面站入网维持周期一致 |
| 步骤 | 配置并记录 `groundStationBeamTimeoutMs` 和 `groundStationJoinMaintainMs`；停止地面站重发或断开地面站，观察卫星载荷是否在超时后不再选择该波束 |
| 验收 | 超时前终端上行可继续转发；超时后终端上行进入缓存或报告无有效地面站波束；地面站重新入网后缓存按 FIFO 刷出 |
| 状态 | 待测 |

备注：第 9 章原文存在“30s 未更新失效”的描述；当前实现和最近需求倾向于与 1 分钟入网维持周期保持一致。测试记录中必须写明本次实际配置值。

### P0-09 服务器下行响应经地面站和卫星载荷转发到终端

| 状态 | 已初验 Data 闭环，Join Accept 需复测 |

### P0-10 无地面站波束时的终端上行缓存

| 项目 | 内容 |
| ---- | ---- |
| 目的 | 验证卫星载荷无有效地面站波束时不丢终端上行，进入 128 条 FIFO 缓存 |

## 6 每次测试必须保存的记录

| 字段 | 说明 |
| ---- | ---- |
