# TK8710 TMS570LS3137 Port Notes

## Target

- MCU: TMS570LS3137 HDK, TI CGT 20.2.7.LTS, EABI, big-endian, `rtsv7R4_T_be_v3D16_eabi.lib`.
- TK8710 physical link: J9 / MibSPI1, master, CPOL=1 / CPHA=0, 8-bit word, MSB first, 16 MHz.
- Default GPIO: `PAD_IRQ` on J11 GIOA3 rising edge; hardware reset on J11 GIOA1.
- Full HAL/TRM build uses the 8 MB external SDRAM at `0x80000000-0x807FFFFF`.

## v1.6 Baseline And Scope

- Functional baseline: committed `D:\CodexWorkSpace\tk8710_hal_v1.6` revision `9662f625`.
- Driver functionality is synchronized while preserving the TMS570 MibSPI/GIO, big-endian register pack and fixed-pool adaptations.
- The TMS570 TRM build supports `TRM_NODE_ROLE_SAT_PAYLOAD` only. Ground gateway and ground station enums remain API-compatible, but `TRM_Init()` returns `TRM_ERR_PARAM` before allocating resources for either unsupported role.
- Satellite payload support includes ground-station beam tracking, 512 terminal routes, a 128-entry uplink cache with 64-byte packets, cached resend, forwarding beam adjustment and payload statistics.
- TMS570 Payload-only TRM uses one 128-entry priority-sorted TX queue with 64-byte payloads. Priority 0 is sent first and equal-priority items retain FIFO order. It also uses a 512-entry beam-release queue and a 128-entry TX result array. Broadcast storage is not allocated; broadcast TX returns `TRM_ERR_STATE`.
- `init_10` is checked/restored at S3. Slave BCN loss tracking starts a runtime watchdog, but state-machine restart runs only from `TK8710ProcessRuntimeWatchdog()` in the main loop.
- Runtime log strings added by this port are ASCII only.

## Added Port

- `rk3506_8710/port/tk8710_tms570.c`
  - Implements TK8710 SPI protocol operations on MibSPI1.
  - Forces MibSPI1 format registers to CPOL=1 / CPHA=0 / 8-bit / MSB first / prescale 4 for 16 MHz when VCLK is 80 MHz, matching the reference `sys_main.c`.
  - Uses manual CS0 control through MibSPI1 GIO pin mode and keeps CS low across a complete TK8710 command.
  - Splits long transfers into MibSPI RAM chunks while preserving the outer transaction CS.
  - Implements GIO IRQ dispatch, RTI tick/delay, SCI log output, critical sections, and SDRAM fixed-pool allocation.
  - Implements absolute `TK8710SleepUntilUs()` timing.
- `rk3506_8710/port/tk8710_tms570.h`
  - Central TMS570 port constants and bring-up API.
- `rk3506_8710/inc/driver/tk8710_platform.h`
  - Platform macros for packed structs, unused attributes, SDRAM placement, malloc/free, file I/O and pthread gating.
  - Wires storage/capture hooks into the Driver. `TK8710PortStorageRead/Write/Erase()` and `TK8710PortCaptureWrite()` currently return unsupported; future backends may use FEE, external Flash or a host data channel without changing Driver logic.
  - `txadc.bin` uses 32 bytes: eight antenna entries, each encoded as signed 16-bit I then signed 16-bit Q in big-endian order. `acm_cal_factors.bin` uses 64 bytes: eight pairs of 32-bit big-endian I/Q factors.
  - `TK8710PortCaptureWrite(stream, NULL, 0)` is the capture-backend capability probe. A supported backend then receives `capture_ant1` through `capture_ant8` streams.

## Memory Map

`source/sys_link.cmd` reserves:

- `SDRAM_TK8710`: origin `0x80000000`, length `0x007F0000` for linked objects.
- `SDRAM_TEST`: origin `0x807F0000`, length `0x00010000`, reserved from application linking.
- `.tk8710_sdram`: TK8710 large buffers, queues, beam tables and fixed heap.
- SDRAM self-test reserve: `0x807F0000-0x807FFFFF` (top 64 KB).
- `.stack`: explicitly placed in `STACKS`.

Current CCS build status:

- `source/sys_main.c` runs board bring-up, Driver/RF init and an AT console for Driver, Loopback, Master and satellite payload TRM tests.
- The temporary SDRAM probe flags used during EMIF address/data-bus debugging have been removed; the retained SDRAM self-test and failure variables are the normal bring-up diagnostics.
- After adding new source files, use CCS `Refresh` + `Clean Project` + `Build Project` so managed makefiles include `trm_satellite.c`.
- After CCS regenerates `Debug/ccsObjs.opt`, it should not contain RK/JTool/test/IPC objects.
- The Payload-only build including `trm_satellite.c` compiles and links with TI CGT 20.2.7.LTS.

Object-level checks show the full TRM objects place large data in `.tk8710_sdram`:

- `trm_data.obj`: the priority-sorted TRM TX queue and TX scratch buffers in `.tk8710_sdram`, `0xd818` bytes.
- `trm_satellite.obj`: payload routes, cache and ground-station beams in `.tk8710_sdram`, `0x4cd8` bytes. The Payload-only build reuses the common TRM beam table instead of allocating the ground-station-only terminal-beam duplicate.
- `trm_beam.obj`: beam table in `.tk8710_sdram`, about `0x400c` bytes.
- `tk8710_irq.obj`: IRQ buffers/state in `.tk8710_sdram`, `0x96c0` bytes.
- `tk8710_tms570.obj`: SPI buffers and fixed heap in `.tk8710_sdram`, about `0x90008` bytes.

The current full Payload-only image uses `0x0b35cd` bytes of linked SDRAM and `0x1cd1` bytes of the general on-chip RAM region, excluding the separately reserved stack region.

## Bring-Up Flow

`source/sys_main.c` now uses the TMS570 path when `PLATFORM_TMS570` is defined:

1. HALCoGen startup calls `systemInit()` before `main()`.
2. `TK8710Tms570Init()` initializes GIO, SCI, RTI, EMIF SDRAM and MibSPI1.
3. `TK8710Tms570SdramSelfTest(0x807F0000, 64 KB)` checks the reserved top-of-SDRAM window.
4. `TK8710SpiReset(TK8710_RST_SM_AND_REG)` issues the TK8710 SPI reset command.
5. `TK8710SpiReadReg(MAC_BASE + 0x0110, ...)` reads `obv_8` for the FPGA version/status bring-up check.
6. `TK8710Init(...)` initializes Driver and RF.
7. IRQ is enabled; register, Tone, Loopback, Master and Payload TRM tests are started with AT commands.

Bring-up status is exposed through CCS variables:

- `g_tk8710BringupStage = 1`: TMS570 port init failed.
- `g_tk8710BringupStage = 2`: SDRAM self-test failed.
- `g_tk8710BringupStage = 3`: TK8710 SPI reset failed.
- `g_tk8710BringupStage = 4`: TK8710 SPI register read failed.
- `g_tk8710BringupStage = 5`: SPI reset and `obv_8` read passed.
- `g_tk8710BringupStage = 6`: Driver debug register write/read test is running.
- `g_tk8710BringupStage = 7`: Driver debug register write/read test failed; check `g_tk8710RegTestRet` and serial log.
- `g_tk8710BringupStage = 8`: Driver debug register write/read test passed; the program then stays in the idle loop by design.
- `g_tk8710BringupReadValue`: raw `obv_8` register value.
- `g_tk8710RegTestRet`: raw `TK8710DebugCtrl(TK8710_DBG_TYPE_REG_RW, ...)` return code.

On `PLATFORM_TMS570`, the Driver debug register test keeps the global register and RF frequency register checks but skips the efuse write/read block.

After board-level SDRAM/SPI checks pass, add the application-specific TK8710 configuration sequence:

1. `TK8710Init(...)`
2. `TK8710Reset(...)`
3. `TK8710RfConfig(...)`
4. `TK8710Start(TK8710_MODE_MASTER, TK8710_WORK_MODE_CONTINUOUS)`
5. `TK8710HalInit(...)`, `TK8710HalCfg(...)`, `TK8710HalStart(...)`, `TK8710HalSendData(...)` for HAL/TRM use.

## Hardware Tests

1. Power-on and confirm SDRAM self-test passes.
2. Probe J9 CS0/CLK/SIMO/SOMI:
   - CS low-active.
   - SPI clock 16 MHz.
   - CPOL=1, CPHA=0.
   - 8-bit words, MSB first.
3. Validate fixed register read/write and TK8710 reset.
4. Validate buffer read/write with payloads crossing one MibSPI RAM chunk.
5. Connect PAD_IRQ to J11 pin 21 / GIOA3 and confirm rising edge enters `TK8710_IRQHandler()`.
6. Start Driver/PHY, then HAL/TRM, and record SDRAM heap peak, SPI error count and IRQ count via `TK8710Tms570GetStats()`.
