# App 版本整合与验证（2026-11-26）

## 行为和来源

本轮将资料目录中的统一灯控、独立 LED supervisor、网络状态观察器和对应测试整合至 apps；纳入此前未提交的 MQTT/GPS 心跳扩展、连接/订阅状态发布、SDK 自动同步及 tk8710_gw 更新。保留仓库的 64 位时间 ABI 构建参数、Mongoose 缺库回退和可配置 SDK_ROOT，并修正 SMP/ipc 的公共依赖相对路径。网络模块保留 SDK 定制中已有的 USB 蜂窝模块 reset/等待串口及 IP/三次失败后 power-cycle 恢复、Wi-Fi 切换容错和断网业务处理，再叠加状态发布。

用户明确选择 WSL 的停止行为。apps/tdaemon/S99tdaemon_job、资料目录同名文件及仓库 SDK overlay 同名脚本与现用 WSL 文件字节一致，SHA-256：`f5e9df5d805c49f0b3b583545b84f1b4e324603e6054ac996d52fd0a4c8d76a5`。停止按配置强制清理业务进程、补充清理手工启动 TK8710、确认退出后硬件复位；不清空双向 IPC，不显式保护 FRP。启动前等待 MQTT ready 的已有功能保留，不随停止策略回退。

build_apps.sh --stage 补齐新版 S37led_agent、led_supervisor.sh、tdaemon_net.sh 和 tdaemon_status.sh 的备份/预置。SDK overlay 的脚本、LED 程序及新增文件清单同步更新。Wi-Fi、Web、FRP 的仓库占位配置保留；本次没有导入现场凭据、原始板端日志和固件镜像。

## 后续构建

在现用 SDK 中构建仓库主线时，显式选择仓库 apps 为来源：

```bash
cd /home/hjh/work/rk3506/rk3506_linux6.1_sdk_v1.2.0
RK3506_APP_SOURCE=/mnt/d/CodexWorkSpace/rk3506b/apps bash external/rk3506app/build_apps.sh --stage
./build.sh buildroot
./build.sh extra-parts
./build.sh updateimg
```

现有 SDK 顶层 build_apps.sh 仍是原入口；若需 B 的时间 ABI/Mongoose 构建改进，应先审查并更新该入口，模块同步不会替换顶层构建脚本。默认 RK3506_APP_SOURCE 未指定时仍读取资料目录；本轮没有更改这个约定。

本轮交付是源码/必要预编译文件的 Git 更新。没有生成或烧录新固件，没有在设备上操作 stop、GPIO、网络或 MQTT。GPIO 电平/射频停发、FRP 断连及恢复、真实 MQTT 服务和最终镜像内文件仍须后续验证。
