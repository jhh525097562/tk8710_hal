# TK8710 主线结构与调用路径梳理

本文档记录当前代码库的主线结构、关键入口、初始化调用路径、中断收发路径、`slotCfg_t`
字段映射，以及当前实现中的几个重要观察项。

目标不是重复目录树，而是给后续阅读和改动提供一条稳定的“顺着代码走”的主线。

## 1. 总结

当前仓库同时存在两条使用路径：

1. 新主线：`HAL -> TRM -> PHY -> Driver -> Port`
2. 旧路径：`Driver/TRM -> Port`

从当前示例、CMake 组织和 `HAL/PHY` 包装层来看，建议优先按新主线理解工程；但底层真实状态、
中断数据面和寄存器落地仍然主要集中在 `src/driver/*`。

一个直接的结论是：

- `HAL` 负责统一入口和状态机。
- `TRM` 负责业务调度、队列、波束、帧推进。
- `PHY` 目前主要是薄包装。
- `Driver` 才是硬件数据面核心。
- `Port` 负责平台相关的 SPI、GPIO、中断线程。

## 3. 主线架构

```text
Example/App
  -> HAL
    -> TRM
      -> PHY wrapper
        -> Driver
          -> Port
            -> TK8710 Hardware
```

对应的核心实现文件：

- HAL：`src/hal/hal_api.c`
- TRM：`src/trm/trm_core.c`、`src/trm/trm_data.c`
- PHY：`src/phy/phy_api.c`
- Driver：`src/driver/tk8710_core.c`、`src/driver/tk8710_config.c`、`src/driver/tk8710_irq.c`
- Port：`port/tk8710_rk3506.c`、`port/jtool/port_jtool.c`

## 4. 初始化主链

推荐从 `test/example/TestTRMmain.c` 的 HAL 用法开始看。

### 4.1 调用路径

```text
TestTRMmain.c
  -> TK8710HalInit()
    -> TK8710HalCbStore()
    -> TK8710HalCbBuildTrmConfig()
    -> TRM_PhyInit()
      -> TK8710PhyInit()
        -> TK8710Init()
          -> TK8710SpiInit()
          -> TK8710Reset(TK8710_RST_ALL)
          -> TK8710GpioInit(... default_gpio_irq_handler ...)
          -> TK8710GpioIrqEnable(0, 1)
          -> 可选 TK8710RfConfig()
          -> 写基础寄存器 init_0/init_5/init_9/irq_ctrl1
      -> TRM_Init()
        -> TRM_BeamInit()
        -> TRM_DataInit()
        -> TRM_RegisterDriverCallbacks()
          -> TK8710RegisterCallbacks()
  -> TK8710HalCfg()
    -> TRM_PhyConfig()
      -> TK8710PhyCfg(TK8710_CFG_TYPE_SLOT_CFG, slotCfg)
        -> TK8710SetConfig(TK8710_CFG_TYPE_SLOT_CFG, slotCfg)
          -> 写时隙/速率/AGC/da_m 等寄存器
          -> 更新 g_slotCfg
          -> 从硬件读回各时隙 timeLen
  -> TK8710HalStart()
    -> TRM_PhyStart()
      -> TK8710PhyStart(TK8710_MODE_MASTER, TK8710_WORK_MODE_CONTINUOUS)
        -> TK8710Start()
          -> 根据主从模式配置 irq_ctrl0
          -> 写 trx_trig0 / trx_trig1 启动收发
```

### 4.2 每层职责

#### HAL

文件：

- `src/hal/hal_api.c`
- `src/hal/hal_cb.c`
- `src/hal/hal_status.c`

职责：

- 统一初始化、配置、启动、发送入口。
- 保存上层回调配置。
- 维护一个简单的 HAL 状态机。

注意：

- `TK8710HalStatusRequireInit()` 和 `TK8710HalStatusRequireConfigurable()` 当前都只是检查
  “状态是否不等于 `UNINIT`”，没有更细的状态约束。

#### TRM/PHY 桥接

文件：

- `src/trm/phy_cfg.c`
- `src/phy/phy_api.c`

职责：

- `TRM_PhyInit = TK8710PhyInit + TRM_Init`
- `TRM_PhyConfig = TK8710PhyCfg(TK8710_CFG_TYPE_SLOT_CFG, ...)`
- `TRM_PhyStart = TK8710PhyStart(master, continuous)`

注意：

- `TRM_PhyStart()` 当前把模式硬编码为 `MASTER + CONTINUOUS`。

#### Driver 初始化

文件：

- `src/driver/tk8710_core.c`

职责：

- 做 SPI 初始化、GPIO 中断挂接、芯片复位。
- 做 RF 初始化。
- 写基础寄存器。
- 在 `TK8710Start()` 中真正开启中断和收发状态机。

注意：

- `TK8710Init()` 当前会连续调用两次 `TK8710RfConfig()`。
- `irq_ctrl0` 的真正配置留到了 `TK8710Start()`，不是在 `TK8710Init()` 内完成。

## 5. 中断与收发主链

中断入口不在 TRM，而在 `Port` 层的 IRQ 线程。

### 5.1 IRQ 进入路径

```text
Port IRQ thread
  -> g_halIrqCallback()
    -> default_gpio_irq_handler()
      -> TK8710_IRQHandler()
        -> 读 irq_res
        -> 清中断
        -> 分发到 tk8710_handle_xxx()
        -> 再按中断类型调用 g_driverCallbacks
```

RK3506 下关键文件：

- `port/tk8710_rk3506.c`
  - `IrqThreadFunc`
  - `TK8710GpioInit`
  - `TK8710GpioIrqEnable`
- `src/driver/tk8710_core.c`
  - `default_gpio_irq_handler`
- `src/driver/tk8710_irq.c`
  - `TK8710_IRQHandler`

### 5.2 Driver 到 TRM 的回调映射

TRM 初始化时会注册这些回调：

```text
onRxData  -> TRM_OnDriverSlotRxAdapter()
onTxSlot  -> TRM_OnDriverTxSlotAdapter()
onSlotEnd -> TRM_OnDriverSlotEndAdapter()
onError   -> TRM_OnDriverErrorAdapter()
```

关键位置：

- `src/trm/trm_core.c`
  - `TRM_RegisterDriverCallbacks`

Driver 中断分发规则：

- `MD_DATA` -> `onRxData(&g_irqResult)`
- `S1` -> `onTxSlot(&g_irqResult)`
- `S0/S2/S3` -> `onSlotEnd(&g_irqResult)`

### 5.3 接收主链：MD_DATA

```text
GPIO IRQ
  -> TK8710_IRQHandler()
    -> tk8710_handle_md_data()
      -> tk8710_md_data_process()
      -> tk8710_md_data_read_signal_info()
    -> g_driverCallbacks.onRxData(&g_irqResult)
      -> TRM_OnDriverSlotRxAdapter()
        -> TRM_OnDriverSlotRx()
          -> TRM_ProcessRxUserDataBatch()
            -> TK8710GetRxUserInfo()
            -> TK8710GetRxUserData()
            -> TRM_SetBeamInfo()
            -> callbacks.onRxData(&rxDataList)
            -> TK8710ReleaseRxData()
```

Driver 接收面的职责：

- 从硬件取 CRC 结果和用户数据。
- 填充 `g_rxBuffers`、`g_userInfoRxBuffers`、`g_irqResult`。
- 提供 `TK8710GetRxUserInfo()`、`TK8710GetRxUserData()` 给上层取数。

TRM 接收面的职责：

- 从 Driver 取一批有效用户。
- 组装 `TRM_RxDataList`。
- 从数据中提取 `userId`。
- 更新 beam 表。
- 调用上层 `onRxData` 回调。

### 5.4 发送主链：S1 时隙

应用调用时并不会立刻下发到芯片，而是先进入 TRM 队列或广播缓存。

```text
应用
  -> TK8710HalSendData()
    -> TRM_PhySendData()
      -> TRM_SetTxData()
        -> 写入 TRM 队列 / 广播缓存

S1 中断到来时：
GPIO IRQ
  -> TK8710_IRQHandler()
    -> tk8710_handle_slot1()
    -> g_driverCallbacks.onTxSlot(&g_irqResult)
      -> TRM_OnDriverTxSlotAdapter()
        -> TRM_OnDriverTxSlot()
          -> TRM_ManageBroadcast()
          -> TRM_ProcessTxSlot()
            -> TK8710SetTxData()
            -> TK8710SetTxUserInfo()
            -> callbacks.onTxComplete(...)
```

Driver 的 S1 行为分成三类：

1. 自动发送：`tk8710_s1_auto_tx_process()`
2. 手动指定信息发送：`tk8710_s1_manual_tx_process()`
3. 广播发送：`tk8710_s1_broadcast_tx_process()`

当前主线 TRM 发送通常依赖“手动指定信息发送”路径。

### 5.5 帧推进与多速率切换：S3 时隙

```text
GPIO IRQ
  -> TK8710_IRQHandler()
    -> tk8710_handle_slot3()
      -> 根据 rateCount / currentRateIndex 切速率
      -> tk8710_configure_multi_rate()
    -> g_driverCallbacks.onSlotEnd(&g_irqResult)
      -> TRM_OnDriverSlotEndAdapter()
        -> TRM_OnDriverSlotEnd()
          -> frameNo++
          -> TRM_SetCurrentFrame(frameNo)
```

这一步会影响：

- 当前速率索引 `currentRateIndex`
- TRM 帧号推进
- 广播调度
- 发送队列发包时使用的速率解释

## 6. `slotCfg_t` 字段说明

定义位置：

- `inc/driver/tk8710_types.h`

全局实例和读写位置：

- 全局实例：`src/driver/tk8710_config.c`
- 读取入口：`TK8710GetSlotConfig()`
- 写入入口：`TK8710SetConfig(TK8710_CFG_TYPE_SLOT_CFG, ...)`

### 6.1 强生效字段

这些字段会直接影响寄存器配置，或者直接决定中断时的数据面行为。

| 字段 | 主要生效点 | 作用 | 改坏后的常见症状 |
| --- | --- | --- | --- |
| `msMode` | `TK8710Start()`、`tk8710_md_data_process()` | 决定主/从/回环模式，以及不同模式下使用哪个时隙长度解释数据 | 无法正常起帧，收发方向错位 |
| `plCrcEn` | `mac_config_1.pl_crc_en` | 控制 payload CRC | 收包 CRC 行为与预期不符 |
| `rateCount` | `tk8710_handle_slot3()` | 决定是否启用多速率轮转 | 速率切换不生效或越界 |
| `rateModes[]` | `mac_config_0.mode`、`tk8710_configure_multi_rate()` | 定义每个速率档位 | 速率模式错、最大用户数解释错 |
| `brdUserNum` | `tk8710_s1_manual_tx_process()`、`tk8710_s1_broadcast_tx_process()` | 定义广播用户数 | 广播 valid 位、频率/AH/Pilot 下发长度错 |
| `antEn` | `init_9.ant_en` | 天线使能 | 某些天线不发或全不发 |
| `rfSel` | `init_9.rf_sel`、RF 配置、扫频 | RF 选择 | 频点配置打不到目标 RF |
| `txBeamCtrlMode` | `init_3.tx_fix_freq`、S1 中断分支 | `0=自动发送`，`1=外部指定信息发送` | S1 走错发送路径，TRM 队列不发包 |
| `txBcnAntEn` | `init_9.tx_bcn_ant_en`、S0 BCN 轮转 | BCN 天线使能或轮转控制 | BCN 固定天线/轮转行为异常 |
| `rx_delay` | `init_1.rx_delay` | 接收窗口偏移 | 接收窗口错位，CRC 错误率上升 |
| `md_agc` | `init_1.md_agc` | DATA AGC 长度 | 接收稳定性、门限表现异常 |
| `s0Cfg[].byteLen` | `mac_config_0.s0_cfg` 语义上保留，当前写死 0 | BCN 时隙字节长度 | 当前主线几乎未显式用作输入 |
| `s1Cfg[].byteLen` | `mac_config_0.s1_cfg` | S1 发送时隙长度 | 广播/FDL 发包长度不匹配 |
| `s2Cfg[].byteLen` | `mac_config_1.s2_cfg`、`tk8710_md_data_process()` | S2 长度 | Master 模式下接收长度解释错误 |
| `s3Cfg[].byteLen` | `mac_config_1.s3_cfg`、`tk8710_md_data_process()` | S3 长度 | Slave/Loopback 模式下接收长度解释错误 |
| `s0/s1/s2/s3Cfg[].da_m` | `init_18/init_2/init_3/init_4` | 时隙尾部空闲时间和内部 DAC 参数 | 帧周期/时隙边界异常 |

### 6.2 运行时派生字段

这些字段不是主要输入，而是配置完成后由硬件读回或由运行时逻辑更新。

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `s0Cfg[].timeLen` | `obv_1` | 配置后从硬件读回 |
| `s1Cfg[].timeLen` | `obv_2` | 配置后从硬件读回 |
| `s2Cfg[].timeLen` | `obv_3` | 配置后从硬件读回 |
| `s3Cfg[].timeLen` | `obv_4` | 配置后从硬件读回 |
| `frameTimeLen` | `s0~s3 timeLen` 累加 | 当前帧总时长 |

### 6.3 条件生效字段

这些字段不是每条链路都用，但在对应功能中是有效的。

| 字段 | 生效条件 | 生效点 |
| --- | --- | --- |
| `bcnRotation[]` | 仅当 `txBcnAntEn == 0xFF` | `tk8710_s0_bcn_rotation_process()` |
| `brdFreq[]` | 广播发送路径 | `tk8710_s1_broadcast_tx_process()` 和手动广播配置路径 |

### 6.4 当前主线中“弱生效/未完全接线”的字段

这些字段定义存在，但在当前主线中没有看到完整寄存器落地。

| 字段 | 当前观察 |
| --- | --- |
| `centerFreq` | 在示例、打印和扫频服务中会设置和展示，但 `TK8710SetConfig(TK8710_CFG_TYPE_SLOT_CFG)` 当前没有直接按它写 RF 频点；实际 RF 频点更依赖 `ChiprfConfig` 和 RF 配置逻辑 |
| `FreqOffset` | 当前未看到明确使用点，像是预留字段 |
| `local_sync` | 字段已定义，但当前主线没有在 `slotCfg` 配置路径中使用；`TK8710Start()` 里会直接写 `init_12.ls_en/ls_master`，没有通过该字段驱动 |

### 6.5 一个容易误判的点

`TK8710SetConfig(TK8710_CFG_TYPE_SLOT_CFG)` 初始化时只会先把 `slotCfg[0]` 写到硬件。  
如果 `rateCount > 1`，其余速率档位要等到 S3 中断时，通过 `tk8710_configure_multi_rate()`
再切进去。

也就是说：

- `slotCfg` 是“整套速率配置”
- 初始上电只装第 0 档
- 后续切换由中断驱动

### 7.2 实际改动时的判断规则

如果一个问题是：

- “初始化起不来”  
  先看 `tk8710_core.c`
- “时隙、速率、帧长不对”  
  先看 `tk8710_config.c` 和 `slotCfg_t`
- “中断到了但上层没收到数据”  
  先看 `tk8710_irq.c -> trm_core.c -> trm_data.c`
- “发送接口调了但没真正发出去”  
  先看 `trm_data.c` 和 `tk8710_handle_slot1`
- “某个平台独有问题”  
  先看对应 `port/*`

## 8. 当前代码的重要观察项

### 8.1 主线与旧路径并存

HAL/PHY 包装层已经建立，但很多测试和底层行为仍然直接走 Driver API。  
结论是：理解工程时必须同时接受“对外新主线”和“内部旧数据面并存”。

### 8.2 `TK8710Init()` 当前会调用两次 `TK8710RfConfig()`

位置在 `src/driver/tk8710_core.c`。  
这不是文档理解层面的抽象问题，而是当前实现中的直接行为。

### 8.3 `TRM_PhyStart()` 硬编码为 `MASTER + CONTINUOUS`

位置在 `src/trm/phy_cfg.c`。  
这意味着走 HAL 主线时，启动模式不是从上层动态传入的。

### 8.4 `slotCfg_t` 不是所有字段都等价“强生效”

当前主线里：

- `byteLen`、`da_m`、`rateModes`、`txBeamCtrlMode` 很关键。
- `centerFreq` 更多是语义配置和打印字段。
- `FreqOffset`、`local_sync` 当前主线接线较弱。

### 8.5 多速率不是初始化一次就结束

`rateCount > 1` 时：

- 初始化只装第 0 档
- 真正的轮转发生在 S3 中断

因此多速率问题不能只看 `TK8710SetConfig()`，必须同时看：

- `tk8710_handle_slot3()`
- `tk8710_configure_multi_rate()`

### 8.6 RK3506 的实际运行链路比 Windows/JTOOL 更完整

Windows/JTOOL 主要适合接口验证和调试。  
IRQ 线程、GPIO、真实硬件收发行为的主链还是以 RK3506 端口实现为准。

## 11. `slotCfg_t` 配置修改后的高频症状速查

下面这张表偏实战排查。遇到问题时，可以先根据“改了什么”和“现在表现是什么”反查最可能的
入口文件。

| 修改项 | 最容易出现的症状 | 优先检查位置 |
| --- | --- | --- |
| `rateModes[]` | 最大用户数解释错误、CRC 暴涨、长度判断错位 | `tk8710_handle_md_data()`、`TRM_ProcessRxUserDataBatch()`、`tk8710_configure_multi_rate()` |
| `rateCount` | 多速率切换不生效，或者 S3 每帧切换异常 | `tk8710_handle_slot3()` |
| `s1Cfg/s2Cfg/s3Cfg[].byteLen` | 写 buffer 长度不匹配、接收截断、帧内用户数据不完整 | `TK8710SetConfig()`、`tk8710_md_data_process()` |
| `s0/s1/s2/s3Cfg[].da_m` | 时隙尾部空闲异常、帧周期不稳、速率切换后边界漂移 | `TK8710SetConfig()`、`tk8710_configure_multi_rate()` |
| `txBeamCtrlMode` | 应用层提交了发送请求，但 S1 实际走了另一套发送路径 | `tk8710_handle_slot1()`、`TRM_ProcessTxSlot()` |
| `brdUserNum` | 广播 valid 位异常、广播用户数不对、广播频率/AH/Pilot 下发长度不对 | `tk8710_s1_broadcast_tx_process()`、`tk8710_s1_manual_tx_process()` |
| `brdFreq[]` | 广播链路频偏、广播用户不可达 | `tk8710_s1_broadcast_tx_process()` |
| `antEn/rfSel` | 某些天线完全不收不发、扫频 RF 不对 | `init_9` 写入点、`TK8710RfConfig()`、`TRM_StartFrequencySweep()` |
| `txBcnAntEn` | BCN 不轮发、固定在错误天线上发 | `tk8710_s0_bcn_rotation_process()` |
| `bcnRotation[]` | BCN 轮发顺序不对，某些天线始终不参与 | `tk8710_s0_bcn_rotation_process()` |
| `rx_delay/md_agc` | 弱信号抓取差、接收窗口偏移、上行数据抓不到 | `TK8710SetConfig()` 写 `init_1` |
| `msMode` | 主从行为错位，接收长度解释错误，触发路径不符合预期 | `TK8710Start()`、`tk8710_md_data_process()` |

## 12. 当前实现中几个值得记住的事实

下面这些不是理想设计，而是当前代码实际表现出来的实现事实。

### 12.1 HAL 主线当前默认只走 `MASTER + CONTINUOUS`

`TK8710HalStart()` 最终会走到：

- `TRM_PhyStart()`
- `TK8710PhyStart(TK8710_MODE_MASTER, TK8710_WORK_MODE_CONTINUOUS)`

这意味着：

- 当前 HAL 主线天然偏向 master 场景。
- 如果后面要从 HAL 主线直接支持 slave/loopback，需要扩展 HAL/TRM 这一层接口。

### 12.2 `TK8710HalStart()` 当前没有强制要求先做 `TK8710HalCfg()`

当前 HAL 状态检查较宽松：

- `TK8710HalStatusRequireInit()`
- `TK8710HalStatusRequireConfigurable()`

本质都是“只要状态不是 `UNINIT` 就通过”。因此行为上存在这种情况：

- `HalInit()` 之后，即使没有显式 `HalCfg()`，`HalStart()` 也可能继续执行。
- 这种情况下，系统可能继续使用已有 `g_slotCfg` 或默认配置。

调试时不能默认假设“当前正在运行的就是这次刚传进去的 `slotCfg_t`”。

### 12.3 `TK8710Init()` 中，带 `rfConfig` 时会调用两次 `TK8710RfConfig()`

位置在 `src/driver/tk8710_core.c`。当前行为是连续两次：

- `ret = TK8710RfConfig(rfCfg);`
- `ret = TK8710RfConfig(rfCfg);`

这属于当前实现现状。阅读或排查 RF 初始化链路时，要把这点纳入考虑。

### 12.4 `txBcnAntEn == 0xFF` 在当前实现里不只是“使能”，还意味着“启用轮发”

当前 S0 逻辑里：

- `txBcnAntEn == 0xFF`：进入 `bcnRotation[]` 轮发模式
- `txBcnAntEn != 0xFF`：关闭轮发，退化为固定行为

所以在当前代码中，它兼具两层语义：

- 天线使能语义
- 模式开关语义

### 12.5 `centerFreq`、`FreqOffset`、`local_sync` 不是当前主线里的强落地字段

当前主线里：

- `centerFreq` 更多是上层配置语义、示例展示和扫频服务配置承载。
- `FreqOffset` 当前几乎未进入关键主链。
- `local_sync` 当前没有看到通过 `slotCfg_t` 系统化驱动；同步更多是 `TK8710Start()` 里的分支硬编码。

因此这些字段即使改了，也不一定会像 `byteLen`、`da_m`、`rateModes` 那样立刻改变主线硬件行为。

### 12.6 `frameTimeLen` 是结果值，不是输入值

当前流程是：

1. 用 `slotCfg_t` 写时隙寄存器
2. 从 `obv_1 ~ obv_4` 读回各时隙时长
3. 累加得到 `frameTimeLen`

所以它更适合作为：

- 配置是否真正生效的验证值
- 帧时序排查时的观测值

而不是直接控制帧周期的输入参数。

### 12.7 多速率不是“初始化一次就结束”

当 `rateCount > 1` 时：

- 初始化只装第 0 档到硬件
- 真正的轮转发生在 S3 中断

因此多速率问题不能只看 `TK8710SetConfig()`，还必须同时看：

- `tk8710_handle_slot3()`
- `tk8710_configure_multi_rate()`
