# 原开发目录与SDK增量同步到Git仓库

入口：`scripts/同步开发目录.ps1`（PowerShell）或`python3 scripts/sync_sources.py`（WSL/Linux）。只写新Git仓库，不改原App、SDK，不编译、不部署、不自动git add/commit/push。

## 第一次使用

```powershell
cd D:\CodexWorkSpace\rk3506b
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\同步开发目录.ps1 -Init
```

`-Init`记录各文件的内容指纹，不复制业务文件。已有基线时拒绝重新初始化，避免掩盖尚未同步的修改。
首次导入遗留的本地/SDK/仓库差异会标记`initial-conflict`，不会因为建立基线而自动认定某份最新。
脚本默认读取本机现有原App目录和WSL SDK；换路径可用`-AppRoot`、`-SdkRoot`和`-Distribution`指定。

## 日常：先比较，再同步选定范围

```powershell
# 比较MQTT，不改源码
.\scripts\同步开发目录.ps1 -Select apps/mqtt

# 确认报告后执行，同步所选范围内无冲突的变化
.\scripts\同步开发目录.ps1 -Apply -Select apps/mqtt

# DTS修改示例
.\scripts\同步开发目录.ps1 -Select sdk/overlay/kernel-6.1/arch/arm/boot/dts/vanxoak-hd-rk3506b-iot-emmc-v1.dts
.\scripts\同步开发目录.ps1 -Apply -Select sdk/overlay/kernel-6.1/arch/arm/boot/dts/vanxoak-hd-rk3506b-iot-emmc-v1.dts
```

在当前PowerShell会话调用时，可传数组选择多个目录：

```powershell
.\scripts\同步开发目录.ps1 -Select apps/mqtt,apps/webserver
```

不带`-Select`会比较全部；不带`-Apply`只写忽略目录中的报告，不改待提交文件。
若所选范围有一个未解决冲突或敏感项，整批拒绝写入。可以缩小`-Select`范围处理其它文件。

## 冲突处理

报告只包含路径、来源、摘要和风险规则，不输出密码或文件内容。

| 状态 | 含义 |
|---|---|
| unchanged | 与已确认版本相同，无需操作 |
| add / update | 新文件或单边变化，可按报告同步 |
| initial-conflict | 第一次记录就存在差异，不能推断哪份最新 |
| conflict | 上次确认后，多方改成了不同内容 |
| repo-only | 仅仓库被手工修改，保留该改动，后续仍参与冲突判断 |
| converged | 多方修改为相同内容，无需覆盖 |

明确选择单个文件来源，参数里的路径是Git仓库相对路径：

```powershell
# 采用Windows原App中的版本
.\scripts\同步开发目录.ps1 -Apply -Select apps/mqtt/src/main.c -Resolve 'apps/mqtt/src/main.c=local'

# 采用SDK中的版本
.\scripts\同步开发目录.ps1 -Apply -Select apps/mqtt/src/main.c -Resolve 'apps/mqtt/src/main.c=sdk'

# 保留仓库版本，并确认当前外部差异是有意的
.\scripts\同步开发目录.ps1 -Apply -Select apps/build_apps.sh -Resolve 'apps/build_apps.sh=repo'
```

需要合并两边代码时先手工合并到仓库，再以`=repo`确认。脚本不会自动拼接代码或根据修改时间选择二进制。
确认后仍会监测下一次变化；`=repo`不是永久忽略该文件。SDK定制文件只有`sdk`和`repo`两个来源。
不能把整目录传给`-Resolve`，必须逐个文件选择，避免不知情地覆盖大量冲突。

## SDK清单及删除

SDK使用`projects.json`记录的基准提交比较，包含未提交以及基准之后已提交的变化，并发现未跟踪的新文件。
新增/修改定制文件会复制到`sdk/overlay/<子仓库>/<路径>`并维护`changes.json`的`files`。
原厂文件被删除时，记录到`delete`；SDK文件恢复为原厂内容时，移除对应overlay及定制清单记录。
不自动更换原厂基线提交。SDK整体升级或新增原厂子项目需要另行更新基线，不由本脚本猜测。

所有实际删除都需要`-AllowDelete`：

```powershell
.\scripts\同步开发目录.ps1 -Apply -Select apps/mqtt/obsolete.c -AllowDelete
```

原App根目录或SDK App根目录缺失时直接拒绝扫描；单个子目录消失可能是删除操作，仍必须检查报告。
首次就缺少某文件不是明确的删除历史；存在初始冲突时还需`-Resolve '路径=local'`等明确选择。
原SDK中缺失对象的无定制仓库（例如当前external/rkwifibt）会在全量报告中列为检查限制；直接选择该仓库时拒绝执行。已有定制记录的仓库不可读取时直接失败，防止漏同步。

## 敏感项、排除项和备份

- 私钥、密码数据库、常见访问令牌及字面量凭据会阻止所选文件写入；显式`-Resolve`也不能绕过。检查是规则扫描，不是完整安全审计。
- 原配置包含真实密码时，手工将非敏感变化合入仓库模板、保留`DEPLOYMENT_REQUIRED`，然后选择`=repo`。不要使用真实密码覆盖脱敏模板。
- 编译目录、日志、固件镜像、备份、历史部署输出、SDK userdata生成目录等被排除。现用`apps/tk8710app`二进制和数据可同步；新文件超过40MiB拒绝复制。
- SDK符号链接保留链接本身，不跟随复制其目标。App符号链接需手工审核。只比较内容和链接目标；单纯chmod变化不作为同步事件。常见文本CRLF/LF差异被归一化。
- `.sync/state.json`保存本机上次确认的指纹；`.sync/runs/<时间>/`保存报告、备份与备份索引。整个`.sync/`已被Git忽略，不能上传。
- `docs/migration-inventory.json`仍是首次导入时的历史清单，不会随日常同步改写；本次同步报告的values字段提供当前文件摘要。
- 写入前重新核对选定源文件和清单；运行期间请暂停编辑。普通复制异常自动恢复本批已修改文件。断电或进程被强杀无法保证自动回滚，可依据backup-index.json恢复；备份包含修改前的仓库文件，不备份原开发目录。
- 更换电脑、删除`.sync`或切换仓库分支后，先检查是否需要独立的基线状态；脚本不替你执行Git切换。换来源根路径会拒绝复用旧状态。

## 同步后提交

```powershell
git status --short
git diff --stat
git diff -- apps/mqtt
# 按变更执行对应构建/验证，再明确选择要提交的文件
git add apps/mqtt
# SDK文件同步时也提交清单
git add sdk/overlay/kernel-6.1 sdk/baseline/changes.json
git diff --cached --stat
git commit -m "说明本次修改"
git push origin main
```

WSL直接调用示例：

```sh
cd /mnt/d/CodexWorkSpace/rk3506b
python3 scripts/sync_sources.py --select apps/mqtt
python3 scripts/sync_sources.py --apply --select apps/mqtt
python3 scripts/test_sync_sources.py
```

退出码：0为正常；预览存在冲突/阻止项返回2；执行被拒绝或运行出错返回1。所有路径选择都基于仓库相对路径，报告文件的绝对路径会在终端打印。
