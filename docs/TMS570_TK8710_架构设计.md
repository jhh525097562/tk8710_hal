# TMS570 TK8710 架构设计

## 1. 总体架构

### 1.1 系统视图

```text
+----------------+          +-----------------------------------------------+          +----------------+
| UART AT Console|          |                TMS570LS3137                   |          |    TK8710      |
| SCI/LIN        |--------->|                                               |--------->| SPI slave     |
+----------------+          | +----------------------+   +----------------+ | MIBSPI3  +----------------+
                            | | 主控/AT模块          |   | TK8710载荷模块 | | master
+----------------+          | | source/sys_main.c    |-->| SatPayloadApp   | |
| FPGA / JTOOL   | MIBSPI1  | +----------+-----------+   | HAL/TRM/Driver  | |
| SPI master     |--------->|            |               +----------------+ |
| 112-byte xfer  | slave    |            v                                  |
+----------------+          | +-------------------------------------------+ |
                            | | FPGA遥控遥测与持久化模块                 | |
                            | | fpga_protocol + fpga_param_store         | |
                            | | SPI1 RC/TM + Bank7 Sector1/2            | |
                            | +----------------------+--------------------+ |
                            +------------------------|----------------------+
                                                     v
                                           Bank7 Data Flash
                                      Sector1: boot flag
                                      Sector2: FPGA params
```

TMS570 内部按模块隔离成三个主要运行模块：

- 主控/AT 模块：负责启动、主循环和 UART AT 控制台。
- TK8710 载荷模块：通过 MIBSPI3 master 控制 TK8710，使用 Driver/HAL/TRM 协议栈。
- FPGA 遥控遥测与持久化模块：通过 MIBSPI1 slave 接收 FPGA/PC master 的固定长度 SPI 帧，并独立管理 Bank7 Sector1/2 数据区。

FPGA 模块与旧 TK8710 代码不做文件级或结构体级耦合；需要 TK8710 生效的命令只通过 `SatPayloadApp` 公共 API 进入载荷模块。

### 1.2 主要代码单元

| 单元 | 文件 | 职责 |
|---|---|---|
| 主控/AT 模块 | `source/sys_main.c` | 平台 bring-up、AT 命令解析、主循环调度。`AT+FPGATM` 只调用 FPGA 模块快照接口，不解析 FPGA 内部存储结构。 |
| FPGA 遥控遥测与持久化模块 | `source/fpga_protocol.c` / `include/fpga_protocol.h` / `source/fpga_param_store.c` / `include/fpga_param_store.h` | 解析 FPGA 遥控帧、构造 112 字节遥测帧、维护 FPGA 参数快照、管理 Bank7 Sector1/2、触发 TMS570 复位。 |
| 卫星载荷应用 | `source/tk8710_sat_payload_app.c` / `include/tk8710_sat_payload_app.h` | 工作参数、工作模式、状态机、TK8710 HAL/TRM 启停、遥测聚合。 |
| TK8710 TMS570 port | `rk3506_8710/port/tk8710_tms570.c` | MIBSPI3、GIO、RTI、SCI 日志、SDRAM、固定堆、capture。 |
| TK8710 协议栈 | `rk3506_8710/src/{driver,phy,hal,trm}` | 芯片寄存器、RF、TRM 队列、扫频、ACM、MAC 解析、业务协议。 |
| HALCoGen 基础 | `source/system.c`、`source/pinmux.c`、`source/mibspi.c`、`source/sci.c` 等 | 启动、时钟、外设、VIM、GIO、RTI、SCI、MIBSPI。 |

### 1.3 模块边界

```text
UART AT
  -> 主控/AT模块(sys_main.c)
      -> TK8710载荷模块(SatPayloadApp)
      -> FPGA遥控遥测与持久化模块(FpgaProtocol_GetSnapshot)

FPGA SPI RC/TM
  -> FPGA遥控遥测与持久化模块(fpga_protocol.c)
      -> Flash子单元(fpga_param_store.c)
      -> TK8710载荷模块公共API(仅0x01/0x02/0x05/0x06和寄存器命令)

TK8710载荷模块
  -> HAL -> TRM -> PHY -> Driver -> TMS570 port -> HALCoGen / hardware
```

当前工程按模块边界分为四个主要域：

| 模块 | 入口文件 | 边界说明 |
|---|---|---|
| 主控/AT 模块 | `source/sys_main.c` | 管理启动、主循环和 UART AT 控制台，不直接实现 FPGA 协议或 Bank7 存储细节。 |
| TK8710 载荷模块 | `source/tk8710_sat_payload_app.c`、`rk3506_8710/` | 管理 TK8710 工作参数、模式、HAL/TRM/Driver，不保存 FPGA boot flag。 |
| FPGA 遥控遥测与持久化模块 | `source/fpga_protocol.c`、`source/fpga_param_store.c` | 管理 SPI1 遥控遥测、FPGA 参数快照、Bank7 Sector1/2 持久化和复位触发。 |

FPGA 遥控遥测与持久化模块是独立模块，不能直接修改 TK8710 Driver 内部状态，也不把 FPGA 自有参数塞进 TK8710 work params。它与旧 TK8710 代码的交互边界只有 `SatPayloadApp_SetWorkMode()`、`SatPayloadApp_SetWorkParams()` 和必要的 telecommand API；Bank7 Sector1/2 的读写由模块内部完成。

## 2. 启动架构

### 2.1 CPU reset 到 main

```text
reset vector
  -> _c_int00()                    source/sys_startup.c
      -> core register/stack init
      -> reset cause snapshot
      -> systemInit()              source/system.c
          -> PLL / clocks
          -> peripheral power
          -> pinmux
          -> EMIF SDRAM startup init
      -> PBIST / ECC / VIM / ESM / MPU
      -> C runtime init
      -> main()                    source/sys_main.c
```

应用层通过 `g_tk8710ResetCause` 打印 `_c_int00()` 入口保存的 reset cause。

### 2.2 main 初始化顺序

`source/sys_main.c` 当前顺序：

```text
main()
  -> TK8710Tms570Init()
      -> GIO / SCI / RTI / EMIF / MIBSPI 基础初始化
  -> print reset cause
  -> SDRAM self-test
  -> if !FPGA_PROTOCOL_SELF_TEST:
       -> TK8710SpiReset()
       -> delay 20 ms
       -> read TK8710 version register
       -> invalid 0/0xFFFFFFFF: halt
     else:
       -> skip TK8710 SPI3 bring-up
  -> SatPayloadApp_Init()
  -> FpgaProtocol_Init()
      -> FPGA 模块加载 Bank7 Sector2 参数或使用默认值
      -> FPGA 模块在快照查询时读取 Bank7 Sector1 boot flag
      -> call SatPayloadApp_SetWorkParams()
      -> call SatPayloadApp_SetWorkMode()
      -> build initial FPGA telemetry frame
      -> configure/arm MIBSPI1 FPGA slave path
  -> enable interrupts
  -> print help and SAT> prompt
  -> while(1) main loop
```

`-FpgaSelfTest` 用于没有连接 TK8710 的 FPGA 模块调试。该模式跳过 TK8710 SPI3 bring-up，但仍进入 FPGA 遥控遥测与持久化模块和 AT 控制台。为了便于调试，`SatPayloadApp_SetWorkParams()` 和 `SatPayloadApp_SetWorkMode()` 在 self-test 编译下只打印调用参数并返回，不访问 8710 硬件。

### 2.3 主循环

```text
while (1)
  -> if !FPGA_PROTOCOL_SELF_TEST:
       -> TK8710Tms570PollIrq()
       -> TK8710ProcessRuntimeWatchdog()
  -> SatPayloadApp_Process()
  -> FPGA 遥控遥测与持久化模块: FpgaProtocol_Process()
  -> SatMainProcessConsole()
```

主循环只调度模块入口，不跨模块访问内部状态：TK8710 后台任务由载荷模块推进，FPGA SPI 遥控遥测由 FPGA 模块推进，UART 命令由主控/AT 模块解析。

## 3. 硬件接口设计

### 3.1 TK8710 SPI3 控制链路

TMS570 到 TK8710 使用 MIBSPI3 master：

- TMS570：MIBSPI3 master。
- TK8710：SPI slave。
- CPOL/CPHA 由 `rk3506_8710/port/tk8710_tms570.c` 配置。
- 主要 API：`TK8710SpiTransfer()`、`TK8710SpiReadReg()`、`TK8710SpiWriteReg()`、`TK8710SpiReadBuffer()`、`TK8710SpiWriteBuffer()`、`TK8710SpiReset()`。

TK8710 控制链路只服务 Driver/HAL/TRM 和 `SatPayloadApp`。FPGA 遥控协议不直接操作 MIBSPI3。

### 3.2 FPGA SPI1 遥控遥测链路

FPGA/PC JTOOL 到 TMS570 使用 MIBSPI1：

- FPGA/JTOOL：SPI master。
- TMS570：MIBSPI1 slave。
- 固定一次 full-duplex 传输 112 字节。
- MOSI 前 10 字节为遥控帧。
- MISO 112 字节为遥测帧。
- 命令执行效果通常在下一帧遥测中确认。

遥控帧：

```text
Byte0  = 0x76
Byte1  = 0x25
Byte2  = CMD
Byte3..8 = PARAM[6]
Byte9  = checksum(Byte2..Byte8 sum low 8-bit)
```

遥测帧：

```text
Byte0..1 = 0xEB90
Byte111  = checksum(Byte2..Byte110 sum low 8-bit)
```

该物理链路只描述 SPI1 传输方式；帧解析、命令语义、参数快照和 Bank7 持久化都属于 FPGA 遥控遥测与持久化模块。

### 3.3 UART AT 控制台

SCI/LIN 控制台用于 bring-up、手工调试和状态查询：

- `AT`：连通性测试。
- `AT+FPGATM`：调用 FPGA 遥控遥测与持久化模块的快照接口，打印协议状态、参数快照和 boot flag。
- `AT+TM`：打印详细 TK8710/载荷遥测。
- `AT+SETPARAM`、`AT+SETMODE`、`AT+SETSWEEP` 等：直接调用 `SatPayloadApp` API。

## 4. FPGA 遥控遥测与持久化模块

FPGA 遥控遥测与持久化模块由 `source/fpga_protocol.c`、`include/fpga_protocol.h`、`source/fpga_param_store.c` 和 `include/fpga_param_store.h` 实现。它是 TMS570 与 FPGA/PC JTOOL 的协议边界，也是 FPGA 参数和升级/回滚标志的存储边界。

模块内部划分为两个子单元，但对外作为一个模块维护：

| 子单元 | 文件 | 职责 |
|---|---|---|
| 协议子单元 | `fpga_protocol.c` / `fpga_protocol.h` | SPI1 帧处理、命令分发、参数快照、遥测帧、复位触发。 |
| 存储子单元 | `fpga_param_store.c` / `fpga_param_store.h` | Bank7 Sector1/2 擦写、record 管理、boot flag 管理。 |

外部模块只应调用协议子单元的公开接口或通过 AT 间接查询，不应直接理解 Sector1/2 的内部 record 格式。

模块职责：

- 校验遥控帧同步字和 checksum。
- 维护 `rxFrameCount`、`rxErrorCount`、`unsupportedCount`、`lastCommandId`。
- 维护 FPGA 参数快照：`mode/rate/slotConfig/txPower/freqHz/rfMask/bootFlag`。
- 对需要 TK8710 生效的命令调用 `SatPayloadApp` 接口。
- 保存 FPGA 自有参数到 Bank7 Sector2。
- 保存升级/回滚 boot flag 到 Bank7 Sector1。
- 对 reset、升级、回滚触发 TMS570 软件复位。

模块不负责：

- 不直接访问 TK8710 Driver 寄存器。
- 不把 `slotConfig` / `txPower` 绑定到 TK8710 work params。
- 不依赖 TK8710 是否连接；`-FpgaSelfTest` 下仍可独立调试 SPI1 协议和 Bank7 存储。

### 4.1 命令行为

| CMD | 名称 | 行为 | 是否保存参数 | 是否调用 TK8710 API |
|---:|---|---|---|---|
| `0x01` | work mode | 更新 `activeMode`，调用 `SatPayloadApp_SetWorkMode()` | 是，Sector2 | 是 |
| `0x02` | rate | 更新 `pendingParams.rates[0].rateMode`，调用 `SatPayloadApp_SetWorkParams()` | 是，Sector2 | 是 |
| `0x03` | slotConfig | 更新 FPGA 自有 `slotConfig` | 是，Sector2 | 否 |
| `0x04` | txPower | 更新 FPGA 自有 `txPower` | 是，Sector2 | 否 |
| `0x05` | frequency Hz | 更新 `centerFreqHz/sweepStartFreqHz/sweepEndFreqHz`，调用 `SatPayloadApp_SetWorkParams()` | 是，Sector2 | 是 |
| `0x06` | rfMask/channel | 更新 `pendingParams.rfMask`，调用 `SatPayloadApp_SetWorkParams()` | 是，Sector2 | 是 |
| `0x07` | reset | 触发 TMS570 软件复位 | 否 | 否 |
| `0x08` | firmware upgrade | 写 Sector1 boot flag = `1`，写完触发 TMS570 软件复位 | 是，Sector1 | 否 |
| `0x09` | data transfer | 当前 unsupported | 否 | 否 |
| `0x0A` | write register | 生产路径转 `SAT_PAYLOAD_TC_WRITE_REG` | 否 | 是 |
| `0x0B` | read register | 生产路径转 `SAT_PAYLOAD_TC_READ_REG` | 否 | 是 |
| `0x0C` | rollback | 写 Sector1 boot flag = `2`，写完触发 TMS570 软件复位 | 是，Sector1 | 否 |
| `0x0D` | UTC seconds | 当前 unsupported | 否 | 否 |
| `0x0E` | DC params | 当前 unsupported | 否 | 否 |

`CMD_03` 和 `CMD_04` 当前没有对应 TK8710 功能接口，因此只作为 FPGA 协议自有参数保存和回显，不绑定到 `SatPayloadWorkParams` 中的 `byteLen` 或 `txGain`。

### 4.2 参数快照

`FpgaProtocolSnapshot` 聚合以下字段：

| 字段 | 来源 |
|---|---|
| `rxFrameCount` / `rxErrorCount` / `unsupportedCommandCount` | FPGA 协议运行计数。 |
| `lastCommandId` | 最近一次合法遥控 CMD。 |
| `workMode` | `g_fpga.activeMode`。 |
| `rateMode` | `g_fpga.pendingParams.rates[0].rateMode`。 |
| `slotConfig` | FPGA 自有参数 `g_fpga.slotConfig`。 |
| `txPower` | FPGA 自有参数 `g_fpga.txPower`。 |
| `centerFreqHz` | `g_fpga.pendingParams.centerFreqHz`。 |
| `rfMask` | `g_fpga.pendingParams.rfMask`。 |
| `bootFlag` | Bank7 Sector1 第 1 字节。 |

`AT+FPGATM` 当前输出格式：

```text
FPGA_TM rxFrames=<n> rxErrors=<n> unsupported=<n> lastCmd=0xXXXXXXXX
FPGA_PARAM mode=<n> rate=<n> slotConfig=<n> txPower=<n> freqHz=<n> rfMask=<n> bootFlag=<n>
OK
```

### 4.3 Bank7 Flash 存储

`fpga_param_store` 是 FPGA 遥控遥测与持久化模块的内部存储单元。它屏蔽 Bank7 data Flash 的 F021 擦写、空白读取和 host-test 模拟细节，对 `fpga_protocol` 提供两类 API：

- FPGA 参数：`FpgaParamStore_Load()` / `FpgaParamStore_Save()`。
- boot flag：`FpgaParamStore_LoadBootFlag()` / `FpgaParamStore_SaveBootFlag()`。

该模块只管理运行时数据 Flash，不负责程序 Flash 烧录，也不负责解释 boot flag 后续进入升级或回滚的业务流程。

#### 4.3.1 存储布局

TMS570 参数和 boot flag 存储在片内 Bank7 data Flash，不占用程序 Flash。

| 区域 | 地址范围 | 大小 | 用途 |
|---|---:|---:|---|
| Bank7 Sector1 | `0xF0204000..0xF0207FFF` | 16 KB | boot flag，第 1 字节有效。 |
| Bank7 Sector2 | `0xF0208000..0xF020BFFF` | 16 KB | FPGA 遥控参数持久化记录。 |

烧录脚本使用 `FlashEraseSelection=1`，避免烧录应用时默认擦除整个 Flash。运行时代码只擦写 Bank7 Sector1 或 Sector2，不擦程序区。

#### 4.3.2 Sector2 参数记录

`source/fpga_param_store.c` 用 32 字节 record 保存 FPGA 参数：

| 字段 | 含义 |
|---|---|
| `magic` | 固定 `0x46504750`。 |
| `version` | 当前版本 `1`。 |
| `length` | `sizeof(FpgaStoredParams)`。 |
| `sequence` | 递增序号，用于选择最新记录。 |
| `workMode` | 工作模式。 |
| `rateMode` | 速率。 |
| `slotConfig` | FPGA 自有时隙配置。 |
| `txPower` | FPGA 自有发射功率。 |
| `centerFreqHz` | 中心频点。 |
| `rfMask` | RF 掩码。 |
| `checksum` | record 校验。 |

保存策略：

- 追加写入空白 record。
- 启动时扫描所有 valid record，选择 `sequence` 最大的一条。
- record 写满后擦除 Sector2 并从第 0 条重新写入。
- Flash 无有效 record 时使用默认参数。

#### 4.3.3 Sector1 boot flag

Sector1 用于升级/回滚请求，当前只定义第 1 字节：

| 值 | 含义 |
|---:|---|
| `0xFF` | 擦除态，无请求。 |
| `0x01` | 固件升级请求。 |
| `0x02` | 回滚请求。 |

`CMD_08` 和 `CMD_0C` 写入流程：

```text
receive CMD_08 or CMD_0C
  -> erase Bank7 Sector1
  -> program first byte as 1 or 2
  -> verify programmed bytes
  -> trigger TMS570 software reset through SYSECR
```

bootloader 或后续启动逻辑可通过 Sector1 第 1 字节判断是否进入升级或回滚流程。

## 5. 载荷应用层设计

### 5.1 工作参数和工作模式

`SatPayloadWorkParams` 是 TK8710 真实工作参数结构，包含：

- `centerFreqHz`
- `rateCount`
- `rates[]` 中的 `rateMode` 和 slot 参数
- `rxGain`
- `txGain`
- `antennaMask`
- `rfMask`
- beacon、sweep、tone、ACM 相关参数

`SatPayloadApp_SetWorkParams()` 只校验并保存 pending 参数；`SatPayloadApp_SetWorkMode()` 基于 pending 参数启动对应模式。启动失败时尝试回滚旧模式，否则进入 `FAULT`。

### 5.2 工作模式

| 模式值 | 枚举 | 功能 |
|---:|---|---|
| `0` | `SAT_PAYLOAD_MODE_SWEEP` | 启动扫频模式。 |
| `1` | `SAT_PAYLOAD_MODE_A` | 普通运行模式 A。 |
| `2` | `SAT_PAYLOAD_MODE_B` | 普通运行模式 B。 |
| `3` | `SAT_PAYLOAD_MODE_C` | 普通运行模式 C。 |
| `4` | `SAT_PAYLOAD_MODE_TONE` | TX tone 调试模式。 |
| `5` | `SAT_PAYLOAD_MODE_ANT_CAL` | ACM 天线校准模式。 |
| `6` | `SAT_PAYLOAD_MODE_CAPTURE` | 连续 capture 模式。 |
| `0xFF` | `SAT_PAYLOAD_MODE_NONE` | 未运行任何模式。 |

### 5.3 状态机

| 状态 | 含义 |
|---|---|
| `CONTROL_READY` | 控制就绪，等待参数或模式命令。 |
| `CONFIGURING` | 正在启动或切换模式。 |
| `RUNNING` | 普通模式运行。 |
| `SWEEP` | 扫频模式。 |
| `TONE` | Tone 调试模式。 |
| `CALIBRATING` | ACM 校准模式。 |
| `CAPTURING` | 连续采集模式。 |
| `RECOVERING` | 新模式失败后恢复旧模式。 |
| `FAULT` | 停止或恢复失败。 |

## 6. AT 控制台设计

### 6.1 主要 AT 命令

| AT 命令 | 功能 |
|---|---|
| `AT` | 连通性测试。 |
| `AT+HELP` | 打印帮助。 |
| `AT+SETPARAM=...` | 设置 pending 工作参数，并保存对应 FPGA 参数视图。 |
| `AT+SETSWEEP=...` | 设置扫频参数。 |
| `AT+SETMODE=<mode>` | 调用 `SatPayloadApp_SetWorkMode()`。 |
| `AT+STOP` | 停止载荷。 |
| `AT+STATE` | 打印应用状态和模式。 |
| `AT+TM` | 打印详细 TK8710/载荷遥测。 |
| `AT+FPGATM` | 打印 FPGA 协议状态、参数快照和 boot flag。 |
| `AT+RREG/WREG` | 读写 TK8710 全局寄存器。 |
| `AT+RRF/WRF` | 读写 RF 寄存器。 |

### 6.2 `AT+FPGATM` 的定位

`AT+FPGATM` 是 FPGA 协议调试入口，不直接读取 TK8710 硬件状态。它输出的是 `FpgaProtocol_GetSnapshot()` 的快照，用于确认：

- SPI 遥控是否被 TMS570 收到。
- 参数是否写入 TMS570 协议上下文。
- Bank7 Sector1 boot flag 是否写入成功。
- 最近命令和错误计数是否符合预期。

## 7. 运行时数据流

### 7.1 FPGA 参数命令数据流

```text
FPGA/JTOOL SPI master
  -> MIBSPI1 slave receives 112-byte full-duplex frame
  -> FPGA遥控遥测与持久化模块: FpgaProtocol_Process()
      -> FpgaHandleRxFrame()
          -> checksum validation
          -> FpgaDispatchCommand()
              -> update g_fpga context
              -> optionally call SatPayloadApp API
              -> save Bank7 Sector2 params or Sector1 boot flag when required
      -> FpgaRefreshTelemetry()
      -> next SPI frame returns updated telemetry
```

### 7.2 模式启动数据流

```text
AT+SETMODE or CMD_01
  -> SatPayloadApp_SetWorkMode(mode)
      -> SatPayloadStartModeWithRollback()
          -> save old active params/mode
          -> SatPayloadStopHal()
          -> build HAL/TRM configuration
          -> TK8710HalInit()
          -> TK8710HalCfg()
          -> TK8710HalStart()
          -> mode-specific action
          -> success: pending -> active
          -> failure: rollback or FAULT
```

### 7.3 TK8710 IRQ 数据流

```text
TK8710 PAD_IRQ
  -> TMS570 GIO/VIM interrupt
  -> ISR only sets pending flag
  -> main loop TK8710Tms570PollIrq()
  -> TK8710_IRQHandler()
  -> Driver callbacks
  -> TRM queue/route/beam handling
  -> SatPayloadApp callbacks update telemetry
```

### 7.4 遥测更新数据流

```text
SatPayloadApp_Process()
  -> every 1000 ms SatPayloadUpdateTelemetry()
      -> platform stats
      -> Driver IRQ counters/status
      -> HAL/TRM status when active
      -> ACM / capture / sweep status
      -> update g_satPayload.telemetry

FpgaProtocol_Process()
  -> refresh 112-byte FPGA telemetry periodically and after RX command
```

## 8. 复位、升级和回滚设计

### 8.1 CMD_07 TMS570 软件复位

`CMD_07` 不再复位 TK8710。当前实现不区分 self-test 或 production，均触发 TMS570 软件复位：

```c
systemREG1->SYSECR = (uint32_t)(0x10U << 14U);
```

写入后代码进入死循环等待复位生效。

### 8.2 CMD_08 固件升级

`CMD_08` 不调用 `SAT_PAYLOAD_TC_FIRMWARE_UPGRADE`，不执行其他业务动作。流程为：

```text
write Bank7 Sector1 first byte = 1
verify write
trigger TMS570 software reset
```

### 8.3 CMD_0C 回滚

`CMD_0C` 不调用回滚 API，不执行其他业务动作。流程为：

```text
write Bank7 Sector1 first byte = 2
verify write
trigger TMS570 software reset
```

## 9. 构建和调试模式

### 9.1 Debug self-test

无 TK8710 硬件连接时使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-tms570.ps1 -Configuration Debug -FpgaSelfTest
```

特点：

- 跳过 TK8710 SPI3 bring-up。
- 保留 FPGA SPI1 遥控遥测。
- `SatPayloadApp_SetWorkParams()` / `SatPayloadApp_SetWorkMode()` 只打印参数并返回，不访问 8710。

### 9.2 Production Debug

连接 TK8710 后使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-tms570.ps1 -Configuration Debug
```

特点：

- 执行 TK8710 SPI reset 和 version read。
- version 为 `0` 或 `0xFFFFFFFF` 时 halt。
- FPGA 参数命令 `0x01/0x02/0x05/0x06` 调用真实 `SatPayloadApp` 接口。

### 9.3 Combined 镜像

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-combined-image.ps1
```

烧录使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\flash-tms570.ps1 -Image Combined
```

Bank7 Sector1/2 是运行时数据区，正常应用烧录不应擦除整片 Flash。

## 10. 设计约束

- FPGA 参数区和 boot flag 区必须与程序 Flash 隔离。
- `CMD_03` 和 `CMD_04` 在 TK8710 无对应功能接口前，只能保存和回显，不允许绑定到 TK8710 work params。
- `CMD_08` 和 `CMD_0C` 只写 boot flag 并复位，不允许附加其他业务动作。
- `CMD_07` 语义是 TMS570 软件复位，不是 TK8710 SPI reset。
- `AT+FPGATM` 用于观察 TMS570/FPGA 协议状态，不替代 `AT+TM` 的 TK8710 详细遥测。
- self-test 模式只用于 FPGA 协议和 Flash 流程验证，不能代表真实 TK8710 硬件链路状态。
