# TRM 时隙计算器枚举分析

## 枚举范围与口径

- 源码：`src/trm/trm_slot.c` 的多速率计算逻辑（单速率、`rateCount=1` 时结果相同）。
- 场景：当前 `test/example/tk8710_gw.c` 主网关路径，`calcType=GROUND_WAN`、广播包块固定为 2。
- 速率模式：5、6、7、8、9、10、11、18。
- `superFrameNum`：1～100。
- 上行、下行包块：分别独立枚举 1～16，共 204,800 组。
- 完整结果 CSV 仅保留 `normal_solution=1`、即找到满足源码约束候选的组合；回退和不支持组合不写入该文件。

全部受支持组合见 `ground_wan_brd2_full_results.csv`，每个速率/超帧的支持边界见
`ground_wan_brd2_support_summary.csv`。

## 计算关系

广播包块固定为 2 时，令 `S = UL包块 + DL包块`：

```text
BRD = 1024 + Body * 5 + BRD_Gap
UL  = 1024 + Body * (2*UL + 1) + UL_Gap
DL  = 1024 + Body * (2*DL + 1) + DL_Gap
RawPeriod = BCN + BRD + UL + DL = C(mode) + 2*Body(mode)*S
```

因此，同一速率下 `(UL=1, DL=5)` 与 `(UL=3, DL=3)` 的周期和支持结论相同；支持关系只取决于上下行包块总和 `S`，但完整 CSV 仍保留了两个独立字段。

正常解必须同时满足：

```text
1 <= M <= 10
1 <= N <= 64
(M * 1,000,000) % N == 0
N % superFrameNum == 0
framePeriod = M * 1,000,000 / N >= RawPeriod
```

计算器在全部候选中选择 `framePeriod - RawPeriod` 最小者。

## 全 1～16 包块均支持的超帧值

这里“全支持”表示 UL、DL 各自 1～16 的 256 种组合都有正常解，即支持 `S=32`。

| 模式 | 全组合正常支持的 superFrameNum |
|---:|---|
| 5 | 1 |
| 6 | 1～2 |
| 7 | 1～4 |
| 8 | 1～6、8 |
| 9 | 1～10、12、16 |
| 10 | 1～10、12、14～16、18、20、24～25、32 |
| 11 | 1～10、12、14～16、18、20、24～25、28、30、32、35～36、40、45、48、50 |
| 18 | 与模式 11 相同 |

其余超帧值可能只支持较小的 `S`，精确上限见支持边界 CSV 的
`max_supported_ul_dl_sum`。某个实际组合满足
`UL + DL <= max_supported_ul_dl_sum` 时才是正常解。由于 UL、DL 最小均为 1，边界小于 2 等价于没有任何受测组合可用。

## 代码层结论与风险

1. `superFrameNum=65～100` 必然无正常解，因为源码把 `N` 限制为最大 64。
2. 即便在 1～64 内，也并非每个值都能求解；例如 11、13、17、19 等值在当前候选集合中没有正常解。不能把“字段能传入”视为“计算器支持”。
3. 多速率函数无解时返回 `framePeriod=totalRawPeriod, frameCount=1, addedGap=0`，同时仍返回 0。该结果没有满足 `N % superFrameNum == 0` 和整秒周期约束，调用方却会把它当作计算成功。
4. 单速率函数无解时没有把 `minGap` 从 `UINT32_MAX` 清零；若任一 `minGapPos` 为 1，会把该值加进时隙长度并发生 32 位回绕。这是明确缺陷。
5. 输入检查实际允许包块到 16，但单速率错误日志仍写 `must be <= 10`，日志与实现不一致。
6. 若多个 `minGapPos` 同时置 1，源码会把完整 `minGap` 重复加入多个时隙，使各时隙之和大于 `framePeriod`；接口应限制只能选择一个位置，或只分配一次 gap。
7. 当前主网关文件使用地面 WAN、广播 2 包块；`tk8710_gw_ground.c` 和 `tk8710_gw_sat.c` 当前则设置为卫星算法且广播为 0，不能直接套用本表，需要按对应口径另算。

## 多速率支持组合（超帧固定为 1）

多速率组合依据 `docs/8710多速率方案说明.md` 第10.4节生成。组合中的第一个模式是
最低速率及BCN同步基准，其余模式只能从该基准模式允许的Data速率中选择；同一组合内不重复模式，
并按速率由低到高排列。模式11与18虽然计算常量相同，但仍作为两个不同协议模式处理。

| 速率数量 | 第10.4节允许的组合数 | 最低包块配置可用 | 每档UL/DL均为1～16时全组合可用 | 部分包块可用 |
|---:|---:|---:|---:|---:|
| 2 | 20 | 20 | 16 | 4 |
| 3 | 31 | 31 | 25 | 6 |
| 4 | 23 | 23 | 19 | 4 |
| 合计 | 74 | 74 | 60 | 14 |

这里的最低包块配置是每个速率均为 `UL=1、DL=1`。多速率运行不枚举其它超帧值，统一使用
`superFrameNum=1`。

- `multi_rate_allowed_combinations.csv`：第10.4节推导出的全部2/3/4速率组合。
- `multi_rate_block_support_sf1.csv`：每个组合在超帧1下的时隙结果和包块支持边界。
- `all_1_to_16_blocks_supported=1`：该组合每档速率的UL、DL各自取1～16均可正常求解。
- `all_1_to_16_blocks_supported=0`：只有满足 `block_support_rule` 的包块配置可用。

多速率原始周期是每档速率原始周期之和。由于各档UL/DL独立枚举会随速率数量指数增长，
完整支持域用CSV中的等价加权不等式表达。例如：

```text
5+6：262144*(UL5+DL5) + 131072*(UL6+DL6) <= 8332737
```

每个包块变量的输入范围仍为1～16。满足该式即存在正常时隙解；超过该式会进入源码回退路径，
不视为支持。

多速率时隙计算器的最大周期仍受源码 `M <= 10` 限制。超帧固定为1时，最大候选周期为
`10,000,000 us`（10秒），所以CSV仅保留满足以下条件的配置：

```text
total_raw_period_us <= max_cycle_us = 10,000,000 us
```

`multi_rate_block_support_sf1.csv` 只保留能找到上述正常候选解的配置，不包含计算器的回退结果。
其中 `normal_solution` 固定为1、`fallback` 固定为0，`support_condition` 记录与源码一致的完整判据，
而不再仅用“原始周期不超过10秒”作为展示判据。
