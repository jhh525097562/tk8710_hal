# TK8710网关运行状态接口

实现：`src/gateway/tk8710_gw.c`接入生命周期；`tk8710_gw_status.c/.h`负责本地快照。
本接口不修改NS协议，不改变GPS强制开关及HAL同步策略。

## 读取

```sh
cat /var/run/tk8710_gw/status.json
```

schema=1；字段：pid、start_ticks、boot_id、state、reason、error_code、gps_enable、business_ready、exited、state_since_mono_ms、updated_mono_ms、phase_timeout_s。
进程身份仅用于本地校验，不新增到NS心跳。时间单位毫秒，时钟CLOCK_MONOTONIC。

## 生命周期

```text
starting → wait_ns_config → configuring
    gps_enable=1 → wait_gps_sync → configuring → wait_pps_alignment → configuring
    gps_enable=0 → configuring
→ running ↔ degraded
→ scanning → configuring/等待GPS及PPS → running
→ stopping → stopped
任一显式致命错误 → fault（锁存首个原因，退出后仍保留）
```

只有配置处理成功、HAL已启动才发布running/business_ready=true。它不代表MQTT已连接，消费者还须检查独立网络和MQTT状态。
wait_gps_sync涵盖UART模块探测和基础GPS/PPS状态获取；wait_pps_alignment表示设置周期后等待输出对齐。
main循环Touch限速1秒，正常运行受原有约10秒轮询影响；GPS/NS等待时仍保持阶段名称，检查点刷新不重置阶段起始时间。

## 消费者必须执行的检查

1. 原子读取JSON，拒绝解析错误、未知schema/状态或不合理字段值。
2. boot_id与本次开机一致；/proc/pid/stat的starttime等于start_ticks；进程身份匹配tk8710_gw，非僵尸。
3. exited=true或进程消失不能视为存活；最终故障文件仅作诊断。
4. running/degraded建议45秒无更新就失效；阶段等待同时检查phase_timeout_s，避免main心跳掩盖配置线程卡住。
5. starting=60、wait_ns_config=35、configuring=120、wait_gps_sync=330、wait_pps_alignment=90、stopping=30秒为显示预算，不是新增业务超时。scanning预算0表示本接口未提供任务deadline，后续须结合扫频服务的超时。
6. fault的首次reason/error_code优先，正常清理不会改写；迟到回调不能重新置为running。

状态写入失败只记告警，不终止业务；没有文件或文件旧时应显示未知/异常。状态目录使用tmpfs，不持续写Flash。没有后台线程虚构业务心跳。
status.lock仅保护快照单写者，不替代网关进程单实例管理。
旧version.txt、GPS策略、GPSinfo.txt和RFstatus.txt保持兼容。GPS信息及MQTT新增字段见下节。

## 故障记录与GPS遥测（2026-10-28）

启动时即配置`8710log/trm_log_*.log`文件输出，NS/GPS初始化阶段的故障也能落盘。
关键退出同时记录`reason/error_code/pid`；IRQ停滞额外记录中断类型、计数、停滞秒数和阈值，
对应原因分别为`md_data_irq_stalled`和`s3_irq_stalled`。
GPS连续异常、RF异常通道数/掩码、TRM退出及接收SIGTERM/SIGINT均写入日志。
默认warn等级会保留启动、停止和故障记录；逐次GPS状态属于info等级。

`/var/run/tk8710_gw/status.json`仍为当前状态；正常清理完成时另原子写入同结构的
`last_exit.json`，新进程启动不覆盖上一轮退出记录，下一次完成清理退出时替换。
它位于tmpfs，只跨进程重启保留，不跨整机重启。SIGKILL/掉电无法执行最终记录；
对此仍需结合当前快照、进程身份和系统日志判断，不能将历史退出当作当前故障。

`gps_enable=1`下，业务主循环每10秒按单调时钟检查GPS，UART查询和扫频/重配置期间可能延后。
启动搜星及周期对齐阶段也会刷新文件。文件使用临时文件+rename原子更新，格式如下：

```ini
lon=114.537037
lat=30.492981
status=18
count=12
avgsnr=35
```

路径保留`/userdata/GPS/GPSinfo.txt`，大小写不变。`status`保持原有连续健康检查计数语义，
不健康归零。`count`直接取AG32 `GET STATUS`的`SATS`（参与定位的卫星数，不是GSV可见总数）；
`avgsnr`取`SNR`，AG32按新鲜GSV中有有效信号值的卫星计算整数平均值。
定位不可用时经纬度按既有行为写0；状态查询成功时仍写本次卫星数和平均SNR；
UART查询失败或模块不可用时新增两项写0，避免保留旧观测。

MQTT工程`apps/mqtt`在`alive`对象中增加同名JSON数值`count/avgsnr`，不改变IPC结构。
旧三行文件或缺失/非法字段上报`null`，与有效观测值0区分。NS需允许并消费这两个附加字段。
每次进程启动，在等待NS配置前先将GPSinfo.txt原子初始化为以下五行；
运行中切换到`gps_enable=0`时再次写入，停止GPS轮询，防止旧数据继续上报：

```ini
lon=unknown
lat=unknown
status=0
count=null
avgsnr=null
```

MQTT读取unknown经纬度不触发旧bdgps回退，count/avgsnr的文本null封包为JSON null。
重新开启GPS后，当前查询结果覆盖默认值。初始化/关闭时写入失败记录ERROR和
`gps_info_init_failed`/`gps_info_reset_failed`故障，并拒绝继续启动/应用配置。

## 构建和测试

```sh
source ~/arm-buildroot-linux-gnueabihf_sdk-buildroot/environment-setup
bash cmake/build_rk3506.sh tk8710_gw tk8710_gw_gps_ns_test
python3 test/example/test_gw_status.py
```

测试环境变量GW_STATUS_TEST_CC选择交叉编译器，GW_STATUS_TEST_RUNNER选择qemu-arm-static及sysroot。
QEMU用户态对自身/proc/stat返回模拟starttime=0，ARM隔离测试用链接包装替换该读取；原生测试使用真实进程身份，其余写入/锁/时钟/线程在两种测试中均真实执行。
本次通过原生和ARM/QEMU状态模块测试及网关目标交叉编译，未做本次新版本板端验收，也未覆盖既有库的全部编译告警。

完整灯语设计位于App工程`light/双色状态灯详细设计.md`：绿常亮正常、绿慢闪准备、红常亮无可用网络、红慢闪业务异常，两色互斥。LED仲裁器及新的MQTT/网络状态生产者属于后续实现，本次仅落地网关生命周期接口。
