# TMS570 遥控、遥测与数传接口说明

> 文档日期：2026-08-13  
> 分析基线：`tms570ls3137_halcogen_base_570RAM_add` 当前工作区源码  
> 结论优先级：当前 `.c/.h` 实现高于旧版设计文档

## 1. 分析结论

当前工程新增了三组主要功能：

1. FPGA 与 TMS570 之间的遥控/遥测协议处理；
2. 外部 SPI Flash 环形缓存和 SPI2 数传；
3. Bank7 参数、直流校准参数、升级/回滚标志和复位次数持久化。

从源码看，遥控命令 `0x01` 到 `0x0E` 已经有分发路径，`0x09` 数传、`0x0D` UTC 时间和 `0x0E` 射频直流参数不再是预留命令。UART 侧也增加了 `AT+FPGATM`、`AT+DTWRITE`、`AT+DTPRINT`、`AT+VER` 和 `AT+RST` 等调试接口。

当前版本已经形成可编译的 CCS 工程，但尚未形成真实硬件联调闭环：

- 2026-08-07 已将 `.cproject` 的工程 include 路径改为 `${PROJECT_ROOT}` 相对路径，并补入本机 F021 Flash API 2.01.01 的头文件与 Cortex-R4 BE32/VFPv3D16 库；
- CCS managed clean build 已成功，`app_status.c`、`data_transfer.c`、`fpga_protocol.c`、`fpga_param_store.c` 和 `spi_flash.c` 均已进入编译和最终链接；
- 临时联调版本定义 `DATA_TRANSFER_SPI2_SLAVE_TEST` 后，将 SPI2 配置为 8 bit 从机，并使用 DMA 请求2/3分别完成 512 字节 RX/TX；正式版本仍规划由 TMS570 作为 SPI2 主机；
- SPI5 外部 Flash 当前尚未完成硬件调试，目标版本通过 `DATA_TRANSFER_SPI_FLASH_ENABLED=0` 禁止初始化、读取、擦除和写入 SPI5 Flash；数传记录暂时只保存在外部 SDRAM 的 64 KiB RAM 缓冲中；
- 四类业务数据已经自动接入数传缓存：Driver/TRM 的 WARN、ERROR 日志，接收帧首个正确用户信息，采数原始数据，以及每轮扫频背景噪声；
- 当前 144 字节遥测长度和每通道 8 字节 ACM 结果已经与 `rk3506_8710/docs/TMS570L与FPGA接口和协议定义_v0.4.pdf` 对齐；四路 ADC、checksum 文字定义和 128 字节物理分页仍需双方进一步统一。

因此本文将状态分成三类：

| 状态 | 含义 |
|---|---|
| 已实现 | 当前源码存在完整处理路径，可以进入编译和联调阶段 |
| 部分实现 | 主流程存在，但初始化、生产数据源或确认机制不完整 |
| 待验证 | 已通过当前工程编译，但尚未通过真实硬件验证 |

## 3. 硬件接口分配

| 链路 | TMS570 角色 | 当前源码外设 | 片选 | 数据宽度 | 用途 |
|---|---|---|---|---|---|
| FPGA 遥控/遥测 | Slave | MIBSPI1 | CS0 | 8 bit | FPGA 下发遥控，TMS570 返回遥测页 |
| TK8710 控制 | Master | MIBSPI3 | CS3 | 8 bit | TK8710 Driver/HAL/TRM 寄存器和数据访问 |
| 数传输出 | 临时测试 Slave；正式规划 Master | SPI2 | CS0 | 8 bit | 临时由 SPI-USB 主机提供时钟，DMA 全双工交换 512 字节；正式版本由 TMS570 主动发送 |
| 外部数据 Flash | Master | MIBSPI5 | CS0 | 8 bit | 保存待下传数据和元数据 |

注意：`source/fpga_protocol.c` 中函数名仍为 `FpgaConfigMibspi3Slave()`，但真正使用的宏是 `mibspiREG1` 和 `mibspiRAM1`。该函数名是遗留命名，不能据此判断 FPGA 链路使用 MIBSPI3。

### 3.1 初始化和主循环

```text
main
  -> TK8710Tms570Init()          MIBSPI3、SCI、RTI、GIO、EMIF
  -> SatPayloadApp_Init()
  -> DataTransfer_Init()         初始化 64 KiB SDRAM 数传缓冲；从机测试版同时初始化 SPI2 DMA
  -> 读取并打印待完成的升级/回滚标志
  -> FpgaProtocol_Init()         恢复参数、复位计数、直流参数并配置 MIBSPI1
  -> while (1)
       -> TK8710 IRQ/Watchdog/SatPayloadApp_Process
       -> FpgaProtocol_Process()
       -> DataTransfer_Process()
       -> UART AT console
```

定义 `DATA_TRANSFER_SPI2_SLAVE_TEST` 时，`DataTransfer_Init()` 会专门配置 SPI2 从机和 DMA 通道2/3，不依赖 `spiInit()`；未定义该宏时仍走原 SPI2 主机同步发送路径。正式主机版仍需统一确认 SPI2 初始化、CS、时钟极性/相位和目标速率。

## 4. 遥控接口

### 4.1 遥控帧

当前遥控有效内容固定为 10 字节，所有多字节参数均按大端序解析。

| 字节 | 内容 |
|---:|---|
| 0 | 同步字 0：`0x76` |
| 1 | 同步字 1：`0x25` |
| 2 | 命令字 CMD |
| 3..8 | 6 字节参数区 |
| 9 | Byte2 到 Byte8 的 8 bit 累加和 |

MIBSPI1 每次实际交换 128 字节，TMS570 只取 MOSI 的前 10 字节作为遥控帧。全 0 轮询帧不满足同步字，按“无遥控命令”处理，不计为协议错误。

### 4.2 命令表

| CMD | 功能 | 当前参数解释 | 执行动作 | 持久化 |
|---:|---|---|---|---|
| `0x01` | 工作模式 | Byte3=`mode` | `SatPayloadApp_SetWorkMode(mode)` | Sector2 |
| `0x02` | 速率 | Byte3=`rateMode` | 设置 `rateCount=1`，调用 `SatPayloadApp_SetWorkParams()` | Sector2 |
| `0x03` | 时隙配置 | Byte3=`slotConfig` | 仅更新 FPGA 协议上下文，未映射到 TK8710 时隙参数 | Sector2 |
| `0x04` | 发射功率 | Byte3=`txPower` | 仅更新 FPGA 协议上下文，未映射到 `txGain` | Sector2 |
| `0x05` | 工作频率 | Byte3..6=`freqHz`，BE32 | 更新中心频率，并把扫频起止频率设为同一频点后应用参数 | Sector2 |
| `0x06` | 射频通道 | Byte3=`rfMask` | 更新 RF mask 并应用参数 | Sector2 |
| `0x07` | TMS570 复位 | 参数未使用 | 写 `SYSECR` 触发软件复位 | 否 |
| `0x08` | 固件升级 | 参数未使用 | Sector1 写 boot flag=1，然后软件复位 | Sector1 |
| `0x09` | 启动数传 | 参数未使用 | `DataTransfer_StartTransmit()`，从当前待传数据头重新开始 | 否 |
| `0x0A` | 写 TK8710 寄存器 | Byte3..4=地址，Byte5..8=值 | 转为 `SAT_PAYLOAD_TC_WRITE_REG` | 否 |
| `0x0B` | 读 TK8710 寄存器 | Byte3..4=设备，Byte5..6=地址 | 转为 `SAT_PAYLOAD_TC_READ_REG`，结果进入遥测 Byte63..70 | 否 |
| `0x0C` | 版本回滚 | 参数未使用 | Sector1 写 boot flag=2，然后软件复位 | Sector1 |
| `0x0D` | UTC 时间 | Byte3..6=累计秒，BE32 | 设置数传记录时间基准 | 否 |
| `0x0E` | RF TX 直流参数 | Byte3=天线，Byte4..5=I，Byte6..7=Q | 转为 `SAT_PAYLOAD_TC_SET_RF_TX_DC` | Sector2 |

UTC 时间以 2009-01-01 00:00:00 为零点。I/Q 直流参数按有符号 16 bit 解释，天线号有效范围为 0..7。

### 4.3 遥控计数语义

`FpgaProtocolSnapshot` 提供以下诊断量：

- `physicalRxFrameCount`：每完成一次 128 字节物理交换加 1，包括全 0 轮询；
- `rxFrameCount`：同步字和 checksum 均合法的遥控帧数；
- `lastPhysicalRxFrame[10]`：最近一次物理交换的前 10 字节；
- `lastCommandId`：最近一次校验通过的命令字；
- `rxErrorCount`：生产编译中只在命令字不支持时增加，不统计同步字错误、checksum 错误或业务执行失败；
- `unsupportedCommandCount`：当前主要在 host/self-test 分支中增加，生产分支通常保持 0。

因此不能把 `rxErrorCount` 当作“所有坏帧数量”。如需定位链路误码，应补充同步字错误、checksum 错误和命令执行错误的独立计数。

## 5. 遥测接口

### 5.1 遥测逻辑帧和物理分页

当前逻辑遥测帧长度为 144 字节，checksum 位于 Byte143。MIBSPI1 一次只能交换 128 字节，因此发送方式为：

| 物理页 | 返回内容 |
|---|---|
| Page0 | 遥测 Byte0..127 |
| Page1 | 遥测 Byte128..143，剩余 112 字节填 0 |

遥测快照每 1000 ms 重新生成一次。物理发送页没有页号、长度或独立校验，且 MISO 数据是在下一次 SPI 交换前预装载的，因此 FPGA 端必须严格维护 Page0/Page1 顺序，并考虑一帧交换延迟。刚上电且首次遥测尚未排队时，返回页可能为全 0。

### 5.2 遥测字段

除特别说明外，多字节字段均为大端序。

| 字节 | 长度 | 当前含义 | 当前实现说明 |
|---:|---:|---|---|
| 0..1 | 2 | 帧头 `0xEB90` | 固定值 |
| 2..17 | 16 | 天线 0..7 噪底 | 每天线 signed Q7：`noiseDbmHz * 128`，范围钳位到 -255..0 |
| 18..19 | 2 | 合路噪底 | 当前固定为 0，未实现 |
| 20 | 1 | 当前工作模式 | `telemetry.activeMode` |
| 21 | 1 | 当前速率 | `activeParams.rates[0].rateMode` |
| 22 | 1 | 时隙配置 | FPGA 协议上下文值 |
| 23 | 1 | 发射功率 | FPGA 协议上下文值 |
| 24..27 | 4 | 中心频率 Hz | `activeParams.centerFreqHz` |
| 28 | 1 | RF mask | `activeParams.rfMask` |
| 29..31 | 3 | 协议版本 | 当前 `1.0.1` |
| 32..35 | 4 | 运行时间 s | `uptimeMs / 1000` |
| 36..39 | 4 | 收包计数 | `telemetry.rxCount` |
| 40..43 | 4 | 发包计数 | `telemetry.txCount` |
| 44 | 1 | 复位次数 | 大于 255 时饱和为 255 |
| 45 | 1 | 复位来源 | 0=normal，1=watchdog，2=other |
| 46 | 1 | RAM 使用率 | `heapUsed * 100 / heapPeak`，最大 100 |
| 47 | 1 | Flash 使用率 | 当前固定为 0 |
| 48 | 1 | CPU 使用率 | 当前固定为 0 |
| 49..60 | 12 | 告警/终端状态预留 | 当前固定为 0 |
| 61..62 | 2 | TK8710 GPIO IRQ 次数 | 仅保留计数低 16 bit |
| 63..64 | 2 | 最近读寄存器设备 | 来自 `0x0B` Byte3..4 |
| 65..66 | 2 | 最近读寄存器地址 | 来自 `0x0B` Byte5..6 |
| 67..70 | 4 | 最近读寄存器值 | 读成功后更新 |
| 71..134 | 64 | 8 路 ACM I/Q 结果 | 每路 8 字节：I 32 bit + Q 32 bit |
| 135..142 | 8 | 预留 | 当前固定为 0 |
| 143 | 1 | checksum | Byte2..142 的 8 bit 累加和 |

ACM 第 `n` 路（n=0..7）的 I 位于 `71 + 8*n`，Q 位于 `75 + 8*n`。

### 5.3 与 v0.4 协议的对齐情况

v0.4 在 2026-08-05 的修订记录中，已经正式将 8 路 ACM 结果从每路 4 字节扩展为每路 8 字节，并把遥测总长度从 112 字节改为 144 字节。当前源码的遥测总长和 ACM 区域与该版本一致。

| 项目 | v0.4 定义 | 当前源码 |
|---|---|---|
| 遥测逻辑长度 | 144 字节 | 144 字节，已对齐 |
| ACM 数据 | Byte71..134，每路 8 字节 | Byte71..134，每路 I/Q 各 32 bit，已对齐 |
| ADC 数据 | Byte135..142，ADC1..4 各 16 bit | 当前固定为 0，尚未接入 ADC 采样值 |
| checksum | Byte143；表格文字仍写“DATA2-110” | Byte143，实际累加 Byte2..142；建议 v0.4 文档将文字修正为 DATA2-142 |
| SPI 交换方式 | FPGA 持续发送 SPI_CS 和 SPI_CLK，顺序接收完整遥测 | TMS570 MIBSPI RAM 每次处理 128 字节，144 字节拆成 Page0/Page1；需 FPGA 明确两次交换时序 |
| 正常启动标志 | Sector1 Byte0=`0xFF` | 应用处理升级/回滚后写为 `0x00`，与 v0.4 定义不一致 |
| 数传命令 `0x09` | 流程允许数据完成或外部命令停止 | 当前忽略参数，只执行启动/重启，没有外部停止处理 |

因此 144 字节本身不再是兼容性问题。当前联调重点应放在 ADC 填充、checksum 描述修订、128 字节分页时序、正常启动标志值和数传停止语义上。

## 6. 数传数据管理

### 6.1 生产数据写入 API

| API | 作用 | 返回值 |
|---|---|---|
| `DataTransfer_AppendBytes(type, data, length)` | 追加二进制记录 | 0 成功，-1 失败 |
| `DataTransfer_AppendString(type, data, length)` | 追加字符串记录 | 0 成功，-1 失败 |
| `DataTransfer_AppendRuntimeLog(text, length)` | 追加 `0x01` 运行日志；初始化前日志直接丢弃，不访问外部 Flash | 0 成功，-1 失败 |
| `DataTransfer_AppendFirstUserInfo(info)` | 序列化并追加 `0x02` 首用户信息 | 0 成功，-1 失败 |
| `DataTransfer_AppendCaptureRawData(chunk)` | 序列化并追加 `0x03` 采数原始数据分块 | 0 成功，-1 失败 |
| `DataTransfer_AppendSweepBackgroundNoise(chunk)` | 序列化并追加 `0x04` 扫频背景噪声分块 | 0 成功，-1 失败 |
| `DataTransfer_SetUtcSeconds(seconds)` | 建立 UTC 与本地运行时间的对应关系 | 无 |
| `DataTransfer_GetPendingLength()` | 查询 Flash+RAM 待传字节数 | 字节数 |
| `DataTransfer_ReadPending(offset, data, length)` | 调试读取待传原始记录 | 实际字节数 |
| `DataTransfer_StartTransmit()` | 对当前待传数据做快照并从包序号 0 开始下传 | 当前总是返回 0 |
| `DataTransfer_GetSnapshot()` | 查询 head/tail/RAM 长度/元数据序号/发送状态 | 无 |

通用 Append API 继续供 `AT+DTWRITE` 调试使用；四个专用 API 已由业务模块自动调用。Driver/TRM 日志在格式化输出时写入 `0x01`，`SatPayloadOnRxData()` 写入 `0x02`，采数完成后写入 `0x03`，每轮扫频完成后写入 `0x04`。

### 6.2 数传数据类型定义

记录头的 1 字节 `type` 统一按下表分配，代码定义位于 `include/data_transfer.h` 的 `DataTransferRecordType`。`0x00` 保留为无效类型，`0x05..0x7F` 保留给后续正式业务，`0x80..0xFF` 保留给地面测试或临时扩展。

| type | 代码枚举 | format | 数据来源与内容 |
|---:|---|---:|---|
| `0x01` | `DATA_TRANSFER_TYPE_RUNTIME_LOG_STATUS` | `1` 字符串 | Driver/TRM 的 WARN、ERROR 日志；INFO 不写入数传缓存 |
| `0x02` | `DATA_TRANSFER_TYPE_FIRST_USER_INFO` | `2` 二进制 | 每个接收帧中的第一个正确用户，包含 frame、user、RSSI、SNR、频率、AH 和 Pilot 功率等信息 |
| `0x03` | `DATA_TRANSFER_TYPE_CAPTURE_RAW_DATA` | `2` 二进制 | 采数状态下每次采集得到的 8 路天线原始数据，每根天线可独立记录或分块记录 |
| `0x04` | `DATA_TRANSFER_TYPE_SWEEP_BACKGROUND_NOISE` | `2` 二进制 | 扫频状态下每轮扫频的频点和各天线背景噪声结果 |

#### 6.2.1 运行日志和状态 `0x01`

使用 `DataTransfer_AppendRuntimeLog()` 写入。payload 是不带结尾 `\0` 的字符串，统一采用：

```text
[module][level] message
```

当前 Driver/TRM 默认日志路径只保存 WARN、ERROR。INFO、DEBUG、TRACE 均不进入数传缓存，UART 原有打印不受影响；首用户明细通过 `0x02` 单独保存。若 Driver 注册自定义日志回调，则该自定义回调分支不会自动写入数传缓存。

#### 6.2.2 首用户信息 `0x02`

TRM 回调只提供 CRC 正确用户；每个接收回调从中保存第一个 `data != NULL && dataLen != 0` 的可读用户。payload 版本 1 固定为 96 字节，多字节整数均为大端：

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 1 | payloadVersion=`1` |
| 1 | 1 | rateMode |
| 2 | 2 | rssi，BE16 有符号数 |
| 4 | 1 | snr |
| 5 | 1 | reserved=`0` |
| 6 | 2 | 用户数据长度 dataLen，BE16 |
| 8 | 4 | frameNo，BE32 |
| 12 | 4 | userId，BE32 |
| 16 | 4 | freqOffset，BE32 有符号数，保持 TK8710 原始单位 |
| 20 | 4 | frequencyHz，BE32 |
| 24 | 8 | pilotPower，BE64 |
| 32 | 64 | `ahData[16]`，每项 BE32，依次为 8 根天线的 I/Q，20 bit 有效值放在低位 |

记录头已经携带 timestamp，因此 payload 不重复保存接收时间。当前在 `SatPayloadOnRxData()` 确认首个可读的 CRC 正确用户后、回调数据失效前完成序列化；每个接收回调最多写一条。

#### 6.2.3 采数原始数据 `0x03`

每次采数完成后，按天线和分块写入。payload 版本 1 的前 20 字节为分块头，后面紧跟原始数据：

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 1 | payloadVersion=`1` |
| 1 | 1 | rateMode |
| 2 | 1 | antenna，`0..7` |
| 3 | 1 | sampleFormat=`1`，有符号 16 bit 原始采样，按大端字节序保存 |
| 4 | 4 | capture generation，BE32 |
| 8 | 4 | bytesPerAntenna，BE32 |
| 12 | 4 | 本块在该天线数据中的 offset，BE32 |
| 16 | 2 | chunkLength，BE16 |
| 18 | 2 | reserved=`0` |
| 20 | N | 原始采样数据，N=`chunkLength` |

同一次采数的所有记录使用相同 generation。当前应用按 antenna、offset 递增，每次主循环最多写一个 1024 字节原始数据块；地面端以 `generation + antenna + offset` 重组，并检查每根天线累计长度等于 `bytesPerAntenna`。8 根天线全部写完前不触发下一次采集，避免双 bank 中待读取数据被下一轮覆盖。单块失败最多重试 3 次，连续失败后放弃该 generation 并记录 ERROR。

#### 6.2.4 扫频背景噪声 `0x04`

每轮扫频完成后按最多 8 个频点分块写入多条记录。payload 版本 1 的前 32 字节为分块头：

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 1 | payloadVersion=`1` |
| 1 | 1 | sweepMode |
| 2 | 1 | rateMode |
| 3 | 1 | antennaCount=`8` |
| 4 | 4 | sweep generation，BE32 |
| 8 | 4 | startFrequencyHz，BE32 |
| 12 | 4 | endFrequencyHz，BE32 |
| 16 | 4 | stepFrequencyHz，BE32 |
| 20 | 4 | totalPoints，本轮总频点数，BE32 |
| 24 | 4 | startIndex，本块第一个频点在本轮中的索引，BE32 |
| 28 | 2 | pointCount，本块频点数，BE16，当前最大为 8 |
| 30 | 2 | reserved=`0` |
| 32 | `pointCount * 36` | 本块频点数组 |

每个频点固定 36 字节：4 字节 `frequencyHz`，随后是天线 0..7 的 8 个 `noiseDbmHz`。噪声值使用 IEEE-754 binary32，先按 32 bit 原始位模式转成大端，禁止直接把编译器结构体连同填充字节写入。地面端以 `generation + startIndex` 重组，并确认累计频点数等于 `totalPoints`。整轮写入失败最多重试 3 次；成功后等待 sweep generation 更新，扫频本身继续循环运行。

### 6.3 内部记录格式

写入外部 Flash 和 RAM 的内容不是裸 payload，而是连续的变长记录：

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 4 | timestamp，BE32 |
| 4 | 1 | format：1=字符串，2=二进制 |
| 5 | 1 | type，由调用者定义 |
| 6 | 2 | payload length，BE16 |
| 8 | N | payload |

`type` 使用 6.2 节定义的全局分配表。收到 UTC 命令前，timestamp 使用本地运行秒数；收到 UTC 命令后，timestamp 使用从 2009-01-01 起算的 UTC 秒数。

### 6.4 外部 Flash 布局

默认外部 Flash 总容量为 64 MiB，扇区 64 KiB，页 256 B。

> 当前目标版本暂时关闭 SPI5 Flash：`DATA_TRANSFER_SPI_FLASH_ENABLED=0`。以下布局保留为后续 SPI5 联调完成后的设计定义，当前运行时不会访问该区域。

| 区域 | 地址 | 大小 | 用途 |
|---|---:|---:|---|
| 元数据扇区 | `0x00000000..0x0000FFFF` | 64 KiB | 保存 head/tail 和递增 sequence |
| 数据环形区 | `0x00010000..0x03FFFFFF` | 1023 个 64 KiB 扇区 | 保存完整数据扇区 |

元数据记录长度为 24 字节，但每条记录占用一个 256 字节页，因此一个元数据扇区可追加 256 次；写满后整扇区擦除。环形队列使用 `head==tail` 表示空，最多可同时标识 1022 个已落盘数据扇区，约 63.875 MiB，另有不足 64 KiB 的当前 RAM 缓冲。

外部 Flash 使用以下 4 字节地址命令：

- `0x13`：Read 4-byte address；
- `0x12`：Page Program 4-byte address；
- `0xDC`：64 KiB Sector Erase 4-byte address；
- `0x06`：Write Enable；
- `0x05`：Read Status。

驱动未读取 JEDEC ID，必须在硬件上确认实际 Flash 支持上述命令、64 KiB 擦除和 64 MiB 容量。

### 6.5 RAM 使用

`DataTransferContext` 内含两个 64 KiB 数组：

- `ram[64 KiB]`：当前写入缓冲；
- `txRam[64 KiB]`：启动数传时对当前 RAM 数据做的发送快照。

连同控制字段，静态占用约 128 KiB。TI 编译器下整个结构通过 `.tk8710_sdram` 放在外部 SDRAM，而不是 TMS570 片内 RAM。链接脚本将该 section 定义为 `NOINIT`。

当前 SPI5 Flash 禁用，因此仅使用 `ram` 保存最多 64 KiB 待传记录；空间不足时 Append API 返回 `-1`，不会触发 Flash 擦写，也不会阻塞业务主循环。复位或掉电后 RAM 数据会丢失。`DataTransfer_Init()` 使用运行 magic 判断 NOINIT 上下文有效性，并显式初始化 UTC、发送状态和相关索引；首次 UTC 同步前使用本地运行秒数作为 timestamp。

临时 SPI2 从机 DMA 路径在 `DataTransferContext` 中增加512字节组帧缓冲，以及TX/RX各512个 `uint32_t` DMA缓冲，共4608字节，均随上下文放在外部SDRAM，不占用片内栈。SPI2的 `BUF/DAT1` 必须采用32位DMA访问：实板确认16位访问不能正确清除RX请求且TX字节会错位。未定义从机测试宏时，原SPI2主机同步发送路径仍会使用较大的栈数组；外部Flash读写路径也有约1 KiB的临时收发数组。当前总栈区为 `0x1500`（5376字节），应通过map和栈水位继续验证。

### 6.6 512 字节数传帧

| 字节 | 长度 | 内容 |
|---:|---:|---|
| 0..3 | 4 | 同步字 `0x1ACFFC1D`，BE32 |
| 4..5 | 2 | 本帧有效数据长度 1..502，BE16 |
| 6..7 | 2 | 包序号，BE16，每次启动从 0 开始 |
| 8..509 | 502 | 记录字节流，不足部分填 `0x5A` |
| 510..511 | 2 | 对 Byte0..509 按大端 16 bit 字求和，取低 16 bit |

临时从机 DMA 模式下，`DataTransfer_Init()` 会调用 `dmaEnable()` 使DMA控制器退出复位；`DataTransfer_Process()` 构造一帧后同时装备 RX DMA 通道2和 TX DMA通道3，再开启SPI DMA请求。两个通道都必须将 `PORTASGN` 配置为4，即本芯片TRM中 `CHxPA=1xx` 对应的Port B；`0xx` 是保留编码。外部主机提供512字节时钟期间由DMA搬运，主循环轮询DMA状态，不再逐字节等待。DMA工作包WCP是只读硬件状态，软件不再写哨兵值；RX通道首次出现 `FTCFLAG` 后才置 `dmaStarted=1`，防止把上一帧残留的WCP值误判为新帧已经开始。实板确认WCP的 `CTCOUNT` 在双通道块完成后仍可能暂时显示RX剩2、TX剩1，因此以RX/TX两通道 `BTCFLAG` 同时置位作为一帧512字节完成的权威条件。装备前还读取一次 `BUF` 清除旧RX请求，避免未装备期间的历史时钟触发新帧。只有双通道BTC完成才确认本地发送成功并准备下一帧。全部快照发送完成后：

`AT+FPGATM` 增加 `dmaStat/dmaPend/dmaEn/dmaBTC/dmaRxRem/dmaTxRem` 状态，并保存最近完整 RX 帧的 `dmaRxFirst/dmaRxLast/dmaRxSum`。例如外部主机发送两轮 `0x00..0xFF` 共 512 字节，预期最近 RX 诊断为首字节 `0x00`、末字节 `0xFF`、16 bit 字节累加和 `0xFF00`。

- 已落盘数据通过推进 tail 从待传队列删除；
- 启动数传时已经存在的 RAM 数据被删除；
- 数传期间后来追加且仍在 RAM 中的数据通过 `memmove` 保留；
- SPI2 发送失败时不清理数据，但没有自动重试；
- 没有 FPGA ACK 或端到端确认，SPI API 返回成功即认为该帧已发送；
- 没有数传停止命令，`0x09` 的参数1/参数2当前均被忽略。

### 6.7 对外数传联调前必须补齐项

以下内容作为后续调试对外数传接口时的明确待办：

1. 正式版本切回 SPI2 master 时，完成 CS0、8 bit 数据宽度、时钟极性/相位和目标速率初始化，并在发送前增加初始化状态检查；临时从机 DMA 路径已实现，但仍需实板时序验证；
2. 定义 `0x09` 参数1/参数2的启动、停止或数据类型语义，至少支持外部停止当前数传；
3. 定义 FPGA 对每个包序号的 ACK/NAK 或状态返回，TMS570 只能在收到成功确认后推进 tail、删除已传数据；
4. 增加发送超时、有限次数重试、重试间隔和最终失败状态，避免单次 SPI 错误后永久停传；
5. 保证相同包序号重发时 FPGA 可以去重，避免 ACK 丢失造成重复入库；
6. 增加发送帧数、确认帧数、重试数、失败数、当前包序号和最后错误码遥测，并提供对应 AT 查询接口；
7. 上板执行断开 SPI2、错误 ACK、超时、传输中停止、传输中复位和重新启动续传等故障注入测试。

## 7. 参数、升级和复位持久化

### 7.1 Bank7 Sector2 参数区

| 项目 | 值 |
|---|---|
| 地址 | `0xF0208000..0xF020BFFF` |
| 大小 | 16 KiB |
| 当前记录版本 | 2 |
| 记录长度 | 64 字节 |
| 可追加记录数 | 256 |

每条记录包含 magic、版本、结构长度、sequence、工作模式、速率、时隙配置、发射功率、中心频率、RF mask、8 路 DC 有效掩码、8 路 I/Q 参数和 checksum。启动时选择 sequence 最大的有效记录；写满后擦除整个 Sector2 并从第 0 条重新写入。读取逻辑兼容旧版 32 字节记录。

无有效记录时使用以下关键默认值：

| 参数 | 默认值 |
|---|---:|
| work mode | 3（模式 C） |
| center frequency | 506500000 Hz |
| rate mode | 6 |
| slot2/slot3 length | 52/52 |
| RX/TX gain | 126/46 |
| antenna/RF mask | `0xFF/0xFF` |
| slotConfig | 0 |
| txPower | 26 |
| ACM calib count/SNR threshold | 1/28 |

通过 FPGA 遥控、`AT+SETPARAM`、`AT+SETMODE` 或 `AT+SETTXDC` 成功修改相关参数后，都会尝试保存到 Sector2。

### 7.2 Bank7 Sector1 boot flag 和复位次数

| 项目 | 值 |
|---|---|
| 地址 | `0xF0204000..0xF0207FFF` |
| 大小 | 16 KiB |
| Byte0 | boot flag |
| Byte1..4 | reset count，BE32 |

boot flag：

- `0xFF`：擦除态/无历史值；
- `0x00`：应用已处理完成；
- `0x01`：请求升级；
- `0x02`：请求回滚。

应用启动时会打印遗留的 1/2 标志，然后 `FpgaProtocol_Init()` 将其清为 0，并递增、保存复位次数。当前保存 reset count 或 boot flag 都会擦除并重写整个 Sector1，因此正常每次上电至少擦除一次 Sector1；需要结合器件擦写寿命评估，建议后续改成追加记录或专用 FEE 管理。

### 7.3 `app_status.c`

`g_appStatus[8]` 被放入 `.app_status` section，包含：

- 固定 magic `0x5A5A5A5A`；
- 应用复位向量 `resetEntry` 地址；
- 日期 `0x20260729`；
- 其余字段当前为 0。

它用于 bootloader 识别应用镜像并跳转到应用复位向量。`.app_status` 已固定在 `0x00020000`，`.intvecs` 固定在 `0x00020020`；入口不能直接指向 `main()`，否则会绕过 `_c_int00` 和应用运行时初始化。当前 2026-08-13 Debug map 已确认 `g_appStatus=0x00020000`、`resetEntry=0x00020020`。

## 8. UART 调试接口

| AT 命令 | 作用 |
|---|---|
| `AT+VER` | 打印 FPGA 协议版本 `1.0.1` |
| `AT+FPGATM` | 打印遥控计数、最近物理帧、参数、boot flag、复位信息、UTC 和读寄存器结果 |
| `AT+DTWRITE=S,<type>,<string>` | 向数传缓存追加字符串记录 |
| `AT+DTWRITE=H,<type>,<hexbytes>` | 向数传缓存追加二进制记录 |
| `AT+DTPRINT=<offset>,<length>` | 按十六进制查看待传原始字节，单次最多 512 字节 |
| `AT+RST` | TMS570 软件复位 |
| `AT+SETPARAM` | 设置工作参数，并同步保存 FPGA 参数视图 |
| `AT+SETMODE` | 切换工作模式，并保存 mode |
| `AT+SETTXDC` | 修改 8 路 RF TX I/Q 直流参数并保存 |

基本缓存测试示例：

```text
AT+DTWRITE=S,1,hello
AT+DTPRINT=0,13
```

预期待传记录总长度为 13 字节：8 字节记录头加 5 字节 `hello`。timestamp 随运行时间变化。

启动数传必须由 FPGA 下发 `0x09` 遥控。若参数区使用 `0xAA` 塥充，完整 10 字节帧为：

```text
76 25 09 AA AA AA AA AA AA 05
```

当前没有 `AT+DTSTART` 和 `AT+DTSTOP`，也没有 AT 命令直接打印 `DataTransferSnapshot`。

## 9. 对外软件接口

### 9.1 FPGA 协议

| API | 使用方 | 说明 |

`SpiFlash_Read()`、`SpiFlash_EraseSector()` 和 `SpiFlash_PageProgram()` 是底层接口。正常业务应通过 `DataTransfer_*` 使用外部 Flash，避免绕过环形队列元数据。
