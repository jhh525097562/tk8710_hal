# RF 射频状态文件

RK3506 网关将现有 ANoise 异常检测结果写入 `/userdata/RFStatus/RFstatus.txt`。

```text
rfstatus=11111111
```

八位字符从左到右对应天线 7、6、5、4、3、2、1、0，与异常掩码 bit7～bit0
一致。`1` 表示尚未被现有检测判为异常，`0` 表示已被判异常并成功禁用。
例如天线 0 异常为 `11111110`；天线 7 异常为 `01111111`；天线 0 和 2
异常为 `11111010`。配置中主动关闭的天线不因此标记为故障。

检测仍使用原有规则：同一天线连续 15 个 ANoise 样本相同，成功清除硬件
`ant_en/rf_sel` 后加入异常掩码。文件不代表新增的射频自检，也不证明未采样天线健康。

启动时写全 1，主循环读取异常掩码，值变化时更新；失败则记录错误并在下一轮重试。
统一退出路径在停止IPC、关闭GPS和清理HAL后，删除 `/userdata/RFStatus` 与
`/userdata/GPS` 中的状态文件及临时文件，保留两个目录，避免退出后被读作在线状态。
驱动重新初始化清零异常掩码后，下一次主循环采样会更新文件。
清理失败会打印文件路径和原因；原退出码为0时改为1，既有非零退出码保持不变。
强制杀进程（SIGKILL）或断电不会执行退出清理。

磁盘操作在主循环中执行，不在 IRQ 内执行。更新延迟受主循环中的 GPS 查询、
初始化和其他阻塞操作影响。使用同目录唯一临时文件和 `rename` 原子替换，目录
权限为 `0755`、文件权限为 `0644`。原子替换避免读到半写文件，不承诺突然断电后
最新快照持久化；消费者可结合文件修改时间与网关进程状态判断快照是否仍有效。

验证：Linux 文件测试覆盖全正常、最低/最高位故障、多位故障、全故障、恢复全正常、
受限 umask 下权限及失败路径；网关 ARM 交叉编译链接通过。本次未注入板端 RF 故障。

```bash
gcc -std=c99 -Wall -Wextra -Werror test/example/test_tk8710_gw_rf_status.c \
    -o /tmp/test_tk8710_gw_rf_status
/tmp/test_tk8710_gw_rf_status
```
