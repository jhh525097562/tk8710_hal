# 首次导入与维护边界

日期：2026-09-23。

## 数据来源及恢复设计

原始SDK和Windows App目录均保留，没有移动、删除或改写其Git历史。
SDK的子仓库基线记录在projects.json；changes.json记录实际导出的修改/新增文件及删除项。
采用完整定制文件overlay加删除清单，而不是直接打包整个SDK或原样导出二进制diff：这样可逐文件脱敏，避免补丁的删除行携带旧密码数据库、配置凭据。
原厂完整源码和工具链仍由原SDK提供，保留SDK原始包是恢复前提。

App以SDK当前集成版本作为构建主线，本地独有工具一起导入；同路径差异另存reference/local-app-variants供复核。
历史日志、固件、压缩备份、生成目录和测试截图未导入。源文件和依赖实际保留清单以Git为准。
旧报告中存在机器绝对路径和历史结果，只作为历史文档，不能当作此次新checkout的验证结果。

## 私有配置

已识别的配置凭据替换为`DEPLOYMENT_REQUIRED`；相关文件列在sanitized-files.json。
SSH测试脚本改从环境变量`RK3506_SSH_PASSWORD`读取连接密码。
系统shadow/gshadow与签名私钥不入库，原始输入保存在当前电脑仓库外的
`D:\CodexWorkSpace\rk3506b-migration-private`，应按私密资料另行备份，禁止提交。
打包前需准备MQTT、FRP、WiFi、Web密码、系统账户及SWU签名材料；不要直接将占位配置烧录到生产网关。
私钥缺失时不能制作可被现有公钥信任的签名升级包，仓库不会生成或替换生产密钥。

## SDK与App同步

以后在本仓库apps和sdk/overlay中维护源文件；恢复脚本面向干净SDK，拒绝覆盖正在开发的SDK。
对已有SDK进行增量同步时，先比较并备份相关文件，不要直接运行递归覆盖命令。
`apps/stage_tk8710app.sh`默认使用版本管理中的同目录tk8710app，不再优先读取另一份Windows绝对路径；需要临时替换时显式指定TK8710_APP_SOURCE。
`apps/build_apps.sh`允许SDK_ROOT指定现有工具链位置，仅编译不带--stage时不会更新固件预置目录。
构建参数与当前Buildroot的64位时间ABI对齐（_TIME_BITS=64、_FILE_OFFSET_BITS=64）；毫秒日志格式作对应类型转换。Mongoose静态库缺失时可从已入库源码构建，避免依赖手工修改的sysroot。
